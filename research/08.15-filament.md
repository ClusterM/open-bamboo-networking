#### 8.15.1. Shared ABI structs

`FilamentQueryParams` and `FilamentDeleteParams` are defined in `bambu_networking.hpp` (ABI ≥ `02.06.00`); `AmsSyncItem` / `AmsSyncParams` land in the same header for **ABI ≥ 02.08.01**:

```cpp
struct FilamentQueryParams {
    std::string category;   // e.g. "PLA", "PETG"
    std::string status;     // "0" = active, "1" = info_needed
    std::string spool_id;   // single id (or comma-list) — sent as ?ids=
    std::string rfid;       // single RFID (or comma-list) — sent as ?RFIDs=
    int offset = 0;
    int limit  = 20;
};
struct FilamentDeleteParams {
    std::vector<std::string> ids;
    std::vector<std::string> rfids;
};

// Present in Studio headers for ABI ≥ 02.08.01
struct AmsSyncItem {
    std::string RFID;
    std::string filamentVendor;
    std::string filamentType;
    std::string filamentName;
    std::string filamentId;
    bool        isSupport      = false;
    std::string color;
    int         colorType      = 0;
    std::vector<std::string> colors;
    int         netWeight      = 0;
    int         totalNetWeight = 0;
    std::string trayIdName;
    std::string note;
    std::string amsSn;
    std::string slotId;
    int         amsId          = 0;
    int         amsType        = 0;
    bool        createNew      = false;
};
struct AmsSyncParams {
    std::string              devId;
    std::vector<AmsSyncItem> items;
};

// Present in Studio headers for ABI ≥ 02.08.02
struct SlotMappingItem {
    std::string amsSn;
    std::string slotId;
    int         spoolId  = 0;
    std::string rfid;
    int         amsId    = 0;
    int         amsType  = 0;
};
struct SlotMappingsSyncParams {
    std::string                  devId;
    std::vector<SlotMappingItem> mappings;
};
```

**Common transport / return contract.** Paths below are relative to the regional API host from [§6.6 Cloud REST API](06.06-cloud-rest.md), under `design-user-service`. Auth is the usual `Authorization: Bearer <access_token>` and `Content-Type: application/json`. Stock `bambu_network_agent/02.06.01.50` / `02.08.01.51` overrides `User-Agent` for this surface (the only place it does so in the entire plugin); the server still accepts the generic `BBL-Slicer/v…` UA. Every call writes the **raw HTTP response body** into `std::string* http_body` and returns `0` or a filament / AMS code from [§8.16](08.16-errors.md) (`BAMBU_NETWORK_ERR_{GET,CREATE,UPDATE,DELETE}_FILAMENT*_FAILED` −27…−31 since `02.06.01`; `BAMBU_NETWORK_ERR_AMS_SYNC_FAILED` −32 for `sync_ams_filaments` since `02.08.01`; `BAMBU_NETWORK_ERR_SLOT_MAPPINGS_SYNC_FAILED` −33 for `sync_slot_mappings` since `02.08.02`) — Studio parses JSON itself; the plugin does not fill a typed out-struct.

Cloud JSON uses camelCase swagger names (`filamentVendor`, `netWeight`, …) from `design-user.api` (`CreateFilamentV2Req` / `UpdateFilamentV2Req` / `ListFilamentV2Resp` / `BatchDeleteFilamentV2Req`). Studio's local spool model is snake_case; `wgtFilaManagerCloudSync` ([wgtFilaManagerCloudSync.cpp](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp)) translates with [`cloud_json_to_spool`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp#L117-L276) / [`spool_to_cloud_json`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp#L278-L346).

`wgtFilaManagerCloudDispatcher` serialises every cloud op onto a single in-flight queue ([`enqueue_pull`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudDispatcher.cpp#L82-L105) / [`enqueue_push_create`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudDispatcher.cpp#L107-L114) / [`enqueue_push_update`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudDispatcher.cpp#L116-L130) / [`enqueue_push_delete`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudDispatcher.cpp#L132-L140)) so the server never sees concurrent writes from the same client. On login, [`GUI_App::on_user_login_handle`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5350-L5385) calls `enqueue_pull()` once a token exists — often the first Filament ABI traffic a plugin sees, before the user opens the tab. Every successful pull rewrites the local store: cloud is source of truth, and local-only entries that never reached the server are dropped.

#### 8.15.8. AMS identity, remain, and `trayIdName`

Studio’s Filament Manager ties cloud catalogue rows to live AMS trays using printer MQTT fields from [§12.1.3](12.01.03-fields-ams.md). Naming is easy to misread: the catalogue / cloud key **`RFID`** maps to the local spool field **`tag_uid`**, but that value is normally the tray’s **`tray_uuid`**, not the NFC chip id. Evidence: Studio source.

##### `tag_uid` vs `tray_uuid` (printer) vs catalogue `RFID`

| Layer | Field | Typical shape | Role |
| --- | --- | --- | --- |
| MQTT tray | `tag_uid` | ~16 hex; all-`0` without RFID | NFC **chip** id (`DevAmsTray::tag_uid`) — which physical tag the AMS reader saw |
| MQTT tray | `tray_uuid` | ~32 hex; all-`0` without RFID | Logical **spool** id (`DevAmsTray::uuid`) — stable across both chips |
| Local store | `FilamentSpool::tag_uid` | same string as cloud `RFID` | Catalogue identity key |
| Cloud JSON | `RFID` | same | Persisted identity for list / update / AMS sync |

**Why two ids (hardware context).** Official Bambu spools carry **two NFC tags** (one on each face). AMS units typically expose only **two readers for four slots**, so a spool may be read from either side depending on orientation / which reader faces which face. The two chips have **different** hardware `tag_uid` values but belong to the **same** spool. Firmware therefore also publishes `tray_uuid` as the shared logical identity; Filament Manager keys the catalogue on that UUID so flipping the spool does not create a second inventory row. This dual-tag layout is hardware / community observation; Studio source never states “two chips” explicitly, but the split below matches that design. *Evidence: Studio field split + match on `uuid`; hardware observation for the dual-tag layout.*

Parser mapping: [`DevFilaSystem.cpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevFilaSystem.cpp#L774) (`tag_uid`) and [`#L802`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevFilaSystem.cpp#L802) (`tray_uuid` → `uuid`). Studio’s own comment in [`match_tray`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerSync.cpp#L218-L234): *`tray.uuid` is the cloud-facing id (same format as stored `spool.tag_uid`); `tray.tag_uid` is the NFC chip id — do not mix them.* Same normalization is mirrored when building AMS→manager create payloads ([`StatusPanel.cpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/StatusPanel.cpp#L5083-L5085), [`AMSItem.cpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/Widgets/AMSItem.cpp#L1495-L1501)).

When the WebView “add from AMS” path exposes an RFID, Studio prefers the tray UUID for official chips: [`normalize_ams_rfid_for_web`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerPanel.cpp#L24-L27) returns `tray_uuid` only when NFC `tag_uid` is length 16 and bytes `[12..13] == "01"`; otherwise the WebView gets an empty RFID string. That `"01"` check is Studio’s “official BBL RFID chip” gate (also used in [`PresetBundle`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/libslic3r/PresetBundle.cpp#L3064)); it is **not** documented as “left vs right face”. Whether the opposite face’s chip uses another suffix (e.g. `"00"`) and still shares the same `tray_uuid` is **unconfirmed** from Studio — capture both faces of one spool if needed.

##### How Studio matches a tray to a catalogue spool

[`wgtFilaManagerSync::match_tray`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerSync.cpp#L218-L234):

1. If `tray.uuid` is non-empty → [`find_by_tag_uid(tray.uuid)`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerStore.cpp#L293-L297) (equality on catalogue `tag_uid` / cloud `RFID`).
2. Hit → that spool.
3. Miss, but `uuid` passes [`is_valid_tag_uid`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerStore.cpp#L141-L148) → **stop** (no fuzzy match). Prevents writing an official RFID tray’s mount/remain onto a manual spool that only shares type/colour.
4. Else → fallback `setting_id` + colour (`tray_info_idx` / `tray_color`).

MQTT **`tag_uid` (chip) is not used in this match.** Validity for catalogue / auto-push is only “non-empty and not all `'0'`” — Studio does **not** require hex length 16/32. Cloud-side schema strictness beyond that is unconfirmed from Studio.

##### Remain weight (path A)

Remain is **printer-sourced**. [`sync_all_trays`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerSync.cpp#L63-L216) reads MQTT `remain` (0–100; see [§12.1.3](12.01.03-fields-ams.md)) and converts to grams with the catalogue’s full net weight:

`net_weight_g = round(effective_total_net_weight × tray.remain / 100)`.

Studio does **not** subtract filament from print jobs for this catalogue. Tray `remain_g` is parsed elsewhere for UI but is **not** the input to this AMS→cloud remain push. Spools with `effective_total_net_weight <= 0` are frozen (no local % / cloud remain update until the user fills total weight). Unmatched trays are skipped — auto-create of new catalogue rows from a live AMS snapshot was removed; new RFID spools enter via the UI “add from AMS” / `create_filament_spool` path.

Throttled cloud push of remain: [`notify_ams_synced`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp#L780-L862) → `update_filament_spool` (path A). Requires a valid catalogue RFID string; while the printer is Busy (printing / calibration / AMS not IDLE), pushes for the same RFID are limited to once per **10 minutes**.

##### `trayIdName`

Cloud / ABI field `trayIdName` (local `tray_id_name`) is a **filament product colour code**, e.g. `"S05-C0"` in the path-B example above — **not** the AMS slot label shown in the Device UI (`A1`, `B2`, …). Slot labels are a separate local `tray_label` derived via `transition_tridid(ams_id * 4 + slot)`.

Sources:

- Printer MQTT `tray_id_name` when present ([§12.1.3](12.01.03-fields-ams.md)).
- If empty on create/update, Studio synthesises [`setting_id.substr(2) + "-" + colorCode`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp#L74-L103) from the filament colour catalogue (e.g. `GFS05` + `C0` → `S05-C0`).

#### 8.15.9. `bambu_network_sync_slot_mappings`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `params` | `SlotMappingsSyncParams` | Printer + slot bindings ([§8.15.1](#8151-shared-abi-structs)). |
| `http_body` | `std::string*` | out: raw HTTP response body. |

**Purpose.** Tell the cloud which catalogue spool sits in which AMS slot (ABI ≥ `02.08.02`). Where `sync_ams_filaments` pushes a spool’s *properties* (weight, colour, vendor) along with its mount fields, this call carries only the binding itself. One payload shape covers both directions: a **bind** names a `spoolId`, an **unbind** sends nothing for it.

**Studio.** The only ABI entry point is [`wgtFilaManagerCloudClient::sync_slot_mappings`](https://github.com/bambulab/BambuStudio/blob/9a530f77c23d8c3430d1dbef02e103cd8bd6480e/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudClient.cpp), reached from two callers in [wgtFilaManagerCloudSync.cpp](https://github.com/bambulab/BambuStudio/blob/9a530f77c23d8c3430d1dbef02e103cd8bd6480e/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp):

- [`sync_slot_bindings_to_cloud(dev_id, spool_ids, is_bind)`](https://github.com/bambulab/BambuStudio/blob/9a530f77c23d8c3430d1dbef02e103cd8bd6480e/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp#L1097-L1177) — a manually entered spool (no valid `tag_uid`) moved into or out of a slot, either from the AMS diff pass or from the material-setting dialog’s OK button.
- [`sync_slot_mappings_to_cloud(dev_id, ejected)`](https://github.com/bambulab/BambuStudio/blob/9a530f77c23d8c3430d1dbef02e103cd8bd6480e/src/slic3r/GUI/fila_manager/wgtFilaManagerCloudSync.cpp#L1051-L1095) — trays that went empty, using the mount values captured *before* the slot was cleared.

Both are driven by [`wgtFilaManagerSync::on_device_update`](https://github.com/bambulab/BambuStudio/blob/9a530f77c23d8c3430d1dbef02e103cd8bd6480e/src/slic3r/GUI/fila_manager/wgtFilaManagerSync.cpp#L264-L305), i.e. by MQTT `push_status` AMS changes for the selected printer. There is no timer and no call on login. RFID trays keep going through `sync_ams_filaments` instead.

Studio does its own filtering before the ABI: it clamps negative `amsId` / `amsType` to `0`, drops any item whose `amsSn` is empty, and — on bind — skips the spool entirely unless it is `cloud_synced` *and* its `spool_id` parses as an `int64`, precisely so a `spoolId` of `0` never leaks out and gets read as an unbind. The response is passed to an empty success lambda; only failures are logged, and −33 gets no special handling.

**Plugin behaviour.** `POST /v1/design-user-service/my/filament/v2/slot-mappings/sync`. Evidence: MITM (`02.08.02.54`).

```json
{
  "devId": "22E8BJ610801473",
  "mappings": [{
    "amsId": 0,
    "amsSn": "19C06A610109584",
    "amsType": 3,
    "rfid": "C0150FF4913D492495F86923A61F8195",
    "slotId": "1",
    "spoolId": 6498430
  }]
}
```

Item keys go out in ASCII order, not struct-declaration order. Two of the six are nullable, and that is what distinguishes an unbind from a bind:

| JSON key  | Source | Notes |
| --------- | ------ | ----- |
| `devId`   | [`MachineObject::get_dev_id()`](https://github.com/bambulab/BambuStudio/blob/9a530f77c23d8c3430d1dbef02e103cd8bd6480e/src/slic3r/GUI/DeviceManager.cpp) | Printer serial. An empty value is *not* filtered locally — it goes out and the server answers **400**. |
| `amsSn`   | spool / snapshot `ams_sn` | Required; an empty value makes the plugin refuse the whole call. |
| `slotId`  | spool / snapshot `slot_id` | A decimal **string** (`"0"`…`"3"`), never a number. Empty is refused. |
| `amsId`   | spool / snapshot `ams_id` | AMS unit index. A literal `0` is sent as `0`, not `null`. |
| `amsType` | spool / snapshot `ams_type` | `DevAmsType`: `0` EXT, `1` AMS, `2` AMS Lite, `3` N3F, `4` N3S, `5` Lite-mixed. A literal `0` is sent as `0`. |
| `rfid`    | spool `tag_uid`, bind only | Serialized as **`null`** when empty. |
| `spoolId` | cloud spool id, bind only | Serialized as **`null`** when `0`. |

The null-mapping is specific to this endpoint: `ams/sync`, captured back to back against the same tray, sends `"RFID": ""` and `"netWeight": 0` verbatim. So an unbind of slot 1 looks like this:

```json
{"devId":"22E8BJ610801473","mappings":[{"amsId":0,"amsSn":"19C06A610109584","amsType":3,"rfid":null,"slotId":"1","spoolId":null}]}
```

Before touching the network, the stock plugin validates every item and returns −33 with an **empty** `http_body` if any of them has an empty `amsSn`, an empty `slotId`, or a negative `amsId`, `amsType` or `spoolId`. Zero is a legal value for all three ints. Neither an empty `devId` nor an empty `mappings` array is caught locally — both are posted, the former yielding 400 and the latter a plain `{"results":[]}`. Evidence: bisected against the stock `02.08.02.54` plugin.

Typical success (200 OK) carries one entry per submitted mapping:

```json
{"results": [{"amsSn": "19C06A610109584", "slotId": "1", "code": 0}]}
```

Observed `code` values: `0` when the mapping was applied, `2` for a `spoolId` that does not exist in the catalogue, and `3` on both requests that carried a non-null `rfid` — including one whose `rfid` genuinely belonged to the submitted `spoolId`, so this looks like an RFID-ownership conflict rather than a plain mismatch. There is no `spoolId` echo here, unlike `ams/sync`.

**Return.** Forward the server body verbatim into `*http_body`. Local validation failure, transport error or non-2xx → `BAMBU_NETWORK_ERR_SLOT_MAPPINGS_SYNC_FAILED` (−33) ([§8.16](08.16-errors.md)).

Hub: [§8](08-abi-main.md).
