### 10.1. What changes when Developer Mode is off

**Developer Mode** is a printer setting. When it is **on**, firmware skips MQTT command-signature checks and typically accepts cleartext `url` / `param` without device-cert field encryption. When it is **off** (“secured” / non–Developer-Mode), the surfaces below gain extra requirements. **LAN-Only** (cloud disabled on the device) is unrelated: it does **not** turn these checks off.

| Surface | Extra requirement (Developer Mode **off**) | Detail |
|---------|--------------------------------------------|--------|
| Privileged MQTT — model URL / G-code fields | Cleartext `url` / `param` replaced by **`url_enc` / `param_enc`** (RSA under the **printer device-cert** public key); encrypt before signing | [§10.3](10.03-mqtt-field-encryption.md) |
| Privileged MQTT commands (`project_file`, `gcode_line`, …) | Envelope must carry a verified `header` (`cert_id`, `sign_string`, `payload_len`, …) signed with the **shared Studio app private key** | [§10.4](10.04-mqtt-signing.md) |
| Printer trust store | Printer must have the app cert (+ CRL) installed via `security.app_cert_install` (RAM; re-install after reboot) or signature verification fails (`…545` / “need reset device pub key”) | [§10.2](10.02-secrets.md#provisioning-printer-trust-store) |
| Shared app credentials | Client needs the current shared app cert chain and private key (stock fetches via cloud cert endpoint; private-key blob finalization still open) | [§10.2](10.02-secrets.md) |
| Cloud REST that starts a print (`POST /v1/user-service/my/task`) | HTTP PoP headers: `x-bbl-app-certification-id`, `x-bbl-device-security-sign` (same app private key; different `cert_id` serialization than MQTT) | [§10.5](10.05-http-pop.md) |
| Same `/my/task` | Hard fingerprint headers `X-BBL-Client-Name: BambuStudio` and matching `X-BBL-OS-Type` (403 otherwise) — independent of Developer Mode, but required for cloud-dispatched prints | [§6.6 Cloud REST API](06.06-cloud-rest.md) |

**Not gated by Developer Mode** (still documented in this chapter because they support the secured path):

| Topic | Notes |
|-------|--------|
| LAN TLS leaf `CN=<serial>`, gaps in Studio `printer.cer` | Always the observed printer cert shape | [§10.6](10.06-lan-tls-and-access-codes.md) |
| Plaintext `dev_access_code` from cloud REST | How cloud-paired printers get the LAN password; not a signature bypass | [§10.6](10.06-lan-tls-and-access-codes.md) |

#### Who verifies

| Check | Consumer |
|-------|----------|
| `header.sign_string` + `header.cert_id` (+ trust store from `app_cert_install`, incl. CRL) | Printer firmware (`84033543`–`84033548`; `…545` = “need reset device pub key”) — algorithms in [§10.4](10.04-mqtt-signing.md) |
| `url_enc` / `param_enc` | Printer decrypts with the device private key — [§10.3](10.03-mqtt-field-encryption.md) |
| `x-bbl-device-security-sign` + `x-bbl-app-certification-id` | Bambu cloud REST — [§10.5](10.05-http-pop.md) |
| Developer Mode **on** | Firmware bypasses signature check; plain `url` / `param` accepted |
