### 10.5. HTTP proof-of-possession

Some cloud REST writes require proof that the client holds the **shared Studio app private key** (same material as MQTT signing — [§10.2](10.02-secrets.md) / [§10.4](10.04-mqtt-signing.md)). The cloud checks two headers; they are independent of the MQTT `header` envelope.

#### Key

| Material | Role |
|----------|------|
| **Shared app private key** | Builds `x-bbl-device-security-sign` (RSA over a timestamp) |
| **App leaf cert** | Supplies `x-bbl-app-certification-id` |

**Not** used here: printer device-cert (that is [§10.3](10.03-mqtt-field-encryption.md) only).

**Also not this chapter:**

| Credential | Role |
|------------|------|
| User `Authorization: Bearer` | Account login — required on `/my/task`, but not the app key |
| `X-BBL-Client-Name` / `X-BBL-OS-Type` | Hard fingerprint on `/my/task` (403 if wrong) — [Cloud HTTP transport](13-http-transport.md); analytics-only on most other routes |

#### Which HTTP requests

| Request | When | Status |
|---------|------|--------|
| **`POST /v1/user-service/my/task`** | Cloud print / hybrid “local print with record” to a **secured** (non–Developer-Mode) printer | **Confirmed** on hardware 2026-07 — both PoP headers required |

RN-6 describes PoP headers more broadly for “secured REST writes.” An endpoint-by-endpoint cloud allowlist has **not** been verified here beyond `/my/task`. Do not assume every authenticated POST needs these headers.

#### How to build the headers

```py
# DIFFERENT serialization from MQTT cert_id (which is serial.lower() + issuer, no separator):
headers["x-bbl-app-certification-id"] = app_cert.issuer + ":" + app_cert.serialNumber.lower()

# Possession token over the current time (NOT a signature over the request body):
timestamp_ms   = str(now_ms())                      # 13-digit decimal string
ciphertext     = RSA_Encrypt(app_private_key, UTF8_Encode(timestamp_ms))  # raw priv-key op, no hash
headers["x-bbl-device-security-sign"] = Base64_Encode(ciphertext)
```

The server recovers the timestamp and checks recency (replay protection). Pitfalls:

- Timestamp must be **milliseconds** (13 digits). A nanosecond value fails recency.
- `x-bbl-app-certification-id` must be `issuer:serial.lower()` — sending the MQTT `cert_id` form **403s**.

#### Practical notes

- Absent a configured app key, **omit** both PoP headers rather than sending blanks.
- MQTT `header` signing ([§10.4](10.04-mqtt-signing.md)) is a separate path; cloud-dispatched prints often never publish MQTT `project_file` at all.
- End-to-end cloud print authorization (trigger semantics, duplicate `/my/task`, fingerprint headers): [§11.2.1](11.02-cloud-upload.md).
