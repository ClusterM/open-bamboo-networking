### 8.2. Callbacks (registration)

After `create_agent` and before `start()`, Studio installs a battery of `std::function` callbacks so the plugin can push events back into the GUI ([§8.1.1](08.01-initialization.md)). Callback typedefs live in [`bambu_networking.hpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/bambu_networking.hpp#L125-L151); setter typedefs / wrappers in [`NetworkAgent.hpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/NetworkAgent.hpp). Most setters are registered from [`GUI_App::init_networking_callbacks`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2036-L2338); SSDP and HTTP-error callbacks are installed later in [`post_init`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1362-L1378) / [`restart_networking`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1938-L1960).

Per-call progress / cancel lambdas (`OnUpdateStatusFn`, `WasCancelledFn`, …) are **not** agent-level setters — they are arguments on bind / print / preset APIs ([§8.6](08.06-bind.md), [§8.8](08.08-print-abi.md), [§8.9](08.09-presets.md)).

#### 8.2.1. Common contract

**Return convention.** Every setter returns `int`: `0` on success, or a `BAMBU_NETWORK_ERR_*` code ([§8.16](08.16-errors.md)) — typically `BAMBU_NETWORK_ERR_INVALID_HANDLE` when `agent` is null / unknown. Passing an empty `std::function` clears the previous callback (Studio does not do this on the happy path).

**Registration timeline.**

1. **`init_networking_callbacks`** ([GUI_App.cpp:2036-2338](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2036-L2338)), called from `on_init_network` before `start()` ([§8.1.1](08.01-initialization.md)): `set_server_callback` → `set_on_server_connected_fn` → `set_on_printer_connected_fn` → `set_get_country_code_fn` → `set_on_subscribe_failure_fn` → `set_on_local_connect_fn` → `set_on_message_fn` → `set_on_user_message_fn` → `set_on_local_message_fn` → `set_queue_on_main_fn`.
2. **`post_init` / `restart_networking`** ([GUI_App.cpp:1362-1378](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1362-L1378), [1938-1960](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1938-L1960)): (re)install **only** `set_on_ssdp_msg_fn` and `set_on_http_error_fn`, then `start_discovery(true, false)`. Those two setters are **not** part of `init_networking_callbacks`.
3. **`set_on_user_login_fn`** is **commented out** in current Studio ([GUI_App.cpp:2041-2043](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2041-L2043)) — the ABI symbol still exists and a compatible plugin must export it.

**Threading.** Most Studio lambdas already marshal UI work with `CallAfter` (or `wxQueueEvent` for HTTP errors). That does **not** replace `QueueOnMainFn`: the plugin must still use `queue_on_main` whenever *it* needs to touch wxWidgets / GUI state from a worker thread. `get_country_code` is a **synchronous** pull and may run on a plugin worker thread — keep it cheap and lock-safe.

#### 8.2.2. `bambu_network_set_queue_on_main_fn`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `fn` | `QueueOnMainFn` | `QueueOnMainFn` — marshal callbacks onto the UI thread. |

**Purpose.** Provide the only safe path for the plugin to run work on Studio's GUI thread.

**Studio.** Registers last inside `init_networking_callbacks` ([GUI_App.cpp:2333-2335](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2333-L2335)): the lambda is `CallAfter(callback)`.

#### 8.2.4. `bambu_network_set_on_http_error_fn`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `fn` | `OnHttpErrorFn` | `OnHttpErrorFn` — non-success cloud HTTP ([§8.2.4](08.02-callbacks.md)). |

**Purpose.** Report HTTP failures from plugin-originated cloud requests to Studio.

**Studio.** Installed alongside SSDP in `post_init` / `restart_networking` ([GUI_App.cpp:1375-1377](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1375-L1377)). Handler [`handle_http_error`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5209-L5216) posts `EVT_HTTP_ERROR` via `wxQueueEvent` (no `CallAfter` in the registered λ).

**Plugin behaviour.** On transport / HTTP errors that Studio should surface globally, invoke with `(http_code, body)`. Keep `body` reasonably small (Studio comments that tips body must be under 1024 bytes).

Evidence: stock `02.08.01.53` via `gap_probe` / `query_bind` when `GET /v1/iot-service/api/user/bind_list?dev_ids=…` returned upstream **502** (APISIX/openresty HTML body): plugin fired `on_http_error(502, "<html>…502 Bad Gateway…")` and still returned `query_bind_status` with `http_code=502` / the same body. So at least cloud REST failures that surface a non-success HTTP status on bind-status use this callback. `set_server_callback` did **not** fire for the same 502.

**Return.** `0` on success; non-zero on failure.

#### 8.2.7. `bambu_network_set_on_server_connected_fn`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `fn` | `OnServerConnectedFn` | `OnServerConnectedFn` — cloud MQTT connect result. |

**Purpose.** Report cloud MQTT broker connect / disconnect outcomes.

**Studio.** ([GUI_App.cpp:2072-2129](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2072-L2129)):
- `return_code == 5` → logout + “Login information expired” dialog.
- `return_code < 0` → homepage MQTT-fail flag + one-shot connect-failed dialog.
- otherwise (`≥ 0`) → clear fail flag, `set_user_selected_machine`, optional multi-machine event, `TryLoadFromMqttCB`, resubscribe cache.

**Plugin behaviour.** Invoke after cloud MQTT `CONNACK` / fatal disconnect with the stock-style `(return_code, reason_code)` pair. Cloud MQTT ABI: [`connect_server`](08.03-cloud-mqtt.md) ([§8.3.3](08.03-cloud-mqtt.md)); sequence in [§8.3.1](08.03-cloud-mqtt.md).

Evidence: `gap_probe` vs stock `02.08.01.53`:

| Outcome | `(return_code, reason_code)` | Notes |
|---------|------------------------------|--------|
| Successful cloud CONNECT | `(0, 0)` | `is_server_connected() == true` |
| Failed connect (missing slicer cert / TLS broken) | `(-1, 255)` | Studio treats `return_code < 0` as MQTT-fail dialog path |

Studio source still documents `return_code == 5` as login-expired (forces logout). That value was **not** reproduced in this probe (would need an expired token on a TLS-healthy path).

**Return.** `0` on success; non-zero on failure.
