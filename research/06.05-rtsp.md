### 6.5. RTSP / RTSPS

On models that use RTSP for live view (X1 / P1S / P2S / H-series and related — not the A1/P1 MJPEG-on-:6000 path), Studio opens an RTSP(S) session to the printer and decodes **H.264** access units.

#### Availability

| Variant | Port | TLS | Typical URL shape (Studio → `Bambu_Create`) |
|---------|------|-----|-----------------------------------------------|
| **RTSPS** | **322** | yes | `bambu:///rtsps___<user>:<passwd>@<ip>/streaming/live/1?proto=rtsps&device=…` |
| **RTSP** | **554** | no | `bambu:///rtsp___<user>:<passwd>@<ip>/streaming/live/1?proto=rtsp&…` |

Path on the printer: **`/streaming/live/1`**. Credentials are the same LAN pair: `user=bblp`, `passwd=` [access code](06-channels.md#access-code). Query params (`device`, `net_ver`, `dev_ver`, `cli_id`, `cli_ver`) are metadata for Studio/analytics — auth is user/passwd.

Which protocol Studio picks is driven by printer capability / `MachineObject` LAN proto (`LVL_Rtsps` / `LVL_Rtsp` / `LVL_Local` for MJPEG). Camera ABI and remote TUTK URLs: [§8.11](08.11-camera.md), [§9](09-abi-bambusource.md).

#### Stream shape

- RTSP(S) signalling + RTP/AVP (or interleaved) carrying **H.264**.
- TLS leaf on RTSPS is the same device cert family (`CN=<serial>`) — optional anti-MITM check as in the [hub](06-channels.md#optional-certificate-check-anti-mitm).
- Deeper SDP/NAL notes: community [OpenBambuAPI `video.md`](https://github.com/Doridian/OpenBambuAPI/blob/master/video.md); Studio consumes samples via `libBambuSource` / `wxMediaCtrl3` FFmpeg decode on current builds.
