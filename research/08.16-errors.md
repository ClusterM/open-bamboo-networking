### 8.16. Error codes

Integer return values for `bambu_network_*` symbols. Canonical macros live in [`bambu_networking.hpp:14-101`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/bambu_networking.hpp#L14-L101) (pin `12f17b06` / ABI series `02.08.01`; snapshot [`tools/abi_snapshot/v02.08.01/bambu_networking.hpp`](../tools/abi_snapshot/v02.08.01/bambu_networking.hpp)). This chapter lists them for research navigation; if the header and a table disagree, trust the header.

Neighbors: per-chapter **Return** notes ([§8.1](08.01-initialization.md)–[§8.15](08.15-filament.md)). **Not** this list: HMS / firmware print-error strings (Studio often parses those from callback `info` via `stoi`); pure-C `ft_err` ([§8.14](08.14-file-transfer.md)).


#### 8.16.1. Common contract

- **`BAMBU_NETWORK_SUCCESS` (`0`)** — call succeeded (or was accepted, for async-style surfaces).
- Negative values are failures. Studio **often ignores** the `int` on MQTT / callback setters; print, bind, preset, filament, and some HTTP paths usually check `result < 0` or a specific code.
- The same macros may appear as the `code` argument of `OnUpdateStatusFn` (especially bind: `-1040` / `-1080` with `info` treated as an HMS code — [§8.6](08.06-bind.md)).
- Print families use header prefixes that match entry points:
  - **WR** → `start_local_print_with_record` ([§8.8.3](08.08-print-abi.md#883-bambu_network_start_local_print_with_record))
  - **SP** → `start_print` ([§8.8.4](08.08-print-abi.md#884-bambu_network_start_print))
  - **LP** → `start_local_print` ([§8.8.2](08.08-print-abi.md#882-bambu_network_start_local_print))
  - **SG** → `start_send_gcode_to_sdcard` ([§8.8.6](08.08-print-abi.md#886-bambu_network_start_send_gcode_to_sdcard))
- Upstream typo (keep exact spelling): `BAMBU_NETOWRK_ERR_PRINT_SP_ENC_FLAG_NOT_READY` (−3140).
- Versioned additions (vs oldest snapshot `02.03.00`): filament −27…−31 since **`02.06.01`**; `AMS_SYNC_FAILED` (−32) since **`02.08.01`**; `SLOT_MAPPINGS_SYNC_FAILED` (−33) since **`02.08.02`**, which also declares the unused −36…−59 block ([§8.16.9](#8169-reserved-print-queue-36-59)).

#### 8.16.9. Reserved — Print Queue (`−36` … `−59`)

`bambu_networking.hpp` `02.08.02` declares 24 Print Queue codes alongside a family of `PrintQueue*` parameter structs. **Studio** doesn't use them yet — `02.08.02.60` has no `NetworkAgent` method, no `dlsym`, and no UI for the feature (its `.po` files only carry obsolete `#~` Print Queue strings). The **plugin**, though, already ships the feature: stock `02.08.02.54` exports 128 `bambu_network_*` symbols against the 110 Studio resolves, and 14 of the 18 extras are Print Queue entry points (`create_print_queue_project`, `get_print_queue_projects`, `start_print_queue_task`, `upload_print_queue_content`, …; the other four are `check_user_report`, `del_rating_picture_oss`, `get_model_instance_id`, `get_model_rating_id`). Nothing is missing in the other direction — every symbol Studio requests is exported.

So the accurate reading is "Studio does not resolve these", not "the plugin does not export them". `−34` and `−35` are skipped. Treat the block as a feature the plugin shipped ahead of its Studio wiring.

Note that [`tools/abi_snapshot/v02.08.02/symbols.txt`](../tools/abi_snapshot/v02.08.02/symbols.txt) is not an inventory of plugin exports — [`tools/check_abi_compat.sh`](../tools/check_abi_compat.sh) generates it by scraping `get_network_function("bambu_network_…")` out of Studio's `NetworkAgent.cpp` at the matching tag, so it records demand, not supply.
