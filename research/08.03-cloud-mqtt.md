### 8.3. Cloud — connection and subscriptions

After the user is logged in ([§8.5](08.05-auth.md) / [§8.5.1](08.05-auth.md)), Studio opens a **cloud MQTT** session and keeps it warm for the lifetime of the login. Typedefs for these entry points live in [`NetworkAgent.hpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/NetworkAgent.hpp#L31-L39); Studio resolves them as `bambu_network_*` via `dlsym` / `GetProcAddress`. Inbound events (`on_server_connected`, `on_message`, `on_user_message`, `on_subscribe_failure`) are registered separately ([§8.2](08.02-callbacks.md)).

Wire-level broker hosts, `u_<user_id>` + token password, topic names, and dual LAN/cloud session policy: [§6.2](06.02-mqtt.md). Command signing / field encryption: [§10](10-non-developer-mode-signing.md). JSON command catalogues: [§12](12-mqtt.md). LAN twin (`connect_printer` / `send_message_to_printer`): [§8.4.3](08.04-lan.md) / [§8.4.5](08.04-lan.md). Single-device cloud selection: [§8.7](08.07-printer-selection.md).


| Symbol                                | Signature                                                                    |
| ------------------------------------- | ---------------------------------------------------------------------------- |
| `bambu_network_enable_multi_machine`  | `void(void* agent, bool enable)`                                             |
| `bambu_network_connect_server`        | `int(void* agent)`                                                           |
| `bambu_network_is_server_connected`   | `bool(void* agent)`                                                          |
| `bambu_network_refresh_connection`    | `int(void* agent)`                                                           |
| `bambu_network_start_subscribe`       | `int(void* agent, std::string module)`                                       |
| `bambu_network_stop_subscribe`        | `int(void* agent, std::string module)`                                       |
| `bambu_network_add_subscribe`         | `int(void* agent, std::vector<std::string> dev_list)`                        |
| `bambu_network_del_subscribe`         | `int(void* agent, std::vector<std::string> dev_list)`                        |
| `bambu_network_send_message`          | `int(void* agent, std::string dev_id, std::string json_str, int qos, int flag)` |


#### 8.3.1. Common contract / sequence

**Return convention.** Most entry points return `int`: `0` on success, or a `BAMBU_NETWORK_ERR_*` code ([§8.16](08.16-errors.md)) — e.g. `BAMBU_NETWORK_ERR_CONNECT_FAILED` (−2), `BAMBU_NETWORK_ERR_SEND_MSG_FAILED` (−4), `BAMBU_NETWORK_ERR_CONNECTION_TO_SERVER_FAILED` (−6020). `is_server_connected` returns `bool`. `enable_multi_machine` returns `void`. Studio **ignores** most `int` returns on this surface; the values that matter in practice are the `bool` from `is_server_connected` (UI gates) and the `int` from `send_message` (propagated to command callers).

**`MessageFlag`** ([bambu_networking.hpp:320-325](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/bambu_networking.hpp#L320-L325)) — bit flags for the `flag` argument of `send_message` / `send_message_to_printer` (passed as plain `int`):

| Value | Enumerator | Meaning |
| ---: | --- | --- |
| `0` | `MSG_FLAG_NONE` | No extra processing requested |
| `1` (`1<<0`) | `MSG_SIGN` | Request MQTT frame signing |
| `2` (`1<<1`) | `MSG_ENCRYPT` | Request privileged-field encryption |

Studio’s `MachineObject::publish_json` defaults `flag=0` and almost always leaves it there; observed call sites pass `qos` (often `1`) but not these bits. On secured printers the plugin still applies signing / field encryption from Developer Mode / cert policy ([§10.3](10.03-mqtt-field-encryption.md) / [§10.4](10.04-mqtt-signing.md)) even when Studio sends `MSG_FLAG_NONE`. Treat the enum as the ABI vocabulary for `flag`; do not assume Studio sets the bits today.

**Lifecycle (after agent `start()`).**

1. **`enable_multi_machine`** during [`on_init_network`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L3694-L3703) (before `start()`), from `app_config["enable_multi_machine"]`.
2. Callbacks already registered ([§8.2](08.02-callbacks.md)).
3. Auth complete ([§8.5.1](08.05-auth.md)) → [`connect_server`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5350-L5355) from `on_user_login_handle` (return unused).
4. Plugin fires [`on_server_connected`](08.02-callbacks.md) ([§8.2.7](08.02-callbacks.md)) → Studio re-selects machine / optional multi-machine resubscribe.
5. While a machine is selected and the user is logged in, [`DeviceManagerRefresher::on_timer`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L974-L1006) calls `refresh_connection` about once per second (timer started/stopped with MainFrame show).
6. On Studio focus active/inactive, idle handler calls `start_subscribe("app")` / `stop_subscribe("app")` ([GUI_App.cpp:3504-3524](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L3504-L3524)).
7. Multi-machine UI uses `add_subscribe` / `del_subscribe` via `DeviceManager::subscribe_device_list`. **Single-machine** cloud selection goes through `set_user_selected_machine` ([§8.7](08.07-printer-selection.md)), not `add_subscribe`.
8. Cloud commands publish through `MachineObject::publish_json` → `cloud_publish_json` → `send_message`.

#### 8.3.2. `bambu_network_enable_multi_machine`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `enable` | `bool` | Multi-machine UI mode on/off (no wire by itself). |

**Purpose.** Tell the agent whether Studio’s multi-machine mode is enabled (affects subscribe / selection behaviour).

**Studio.** [`DeviceManager::EnableMultiMachine`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L65-L68) from [`on_init_network`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L3694-L3703) with `true`/`false` from `app_config`. Called while constructing the agent path — before `set_country_code` / `start()`.

**Plugin behaviour.** Store the flag for later multi-device subscribe / selection policy. No network I/O inside this call.

Evidence: `gap_probe` vs stock `02.08.01.53` on a live cloud MQTT session (`server_connected` `(0,0)`): toggling `enable_multi_machine(true)` then `false` produced **no** additional MQTT packets on `us.mqtt.bambulab.com:8883` (tcpdump during the window). Wire subscribe changes for multi-machine go through `add_subscribe` / `del_subscribe` / selection ([§8.3.8](#838-bambu_network_add_subscribe)), not this setter alone.

**Return.** `void`.

#### 8.3.3. `bambu_network_connect_server`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |

**Purpose.** Open (or start opening) the regional cloud MQTT broker session after the user has a valid login token.

**Studio.** Invoked from [`GUI_App::on_user_login_handle`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5350-L5355) immediately after login handling begins. Return value is **ignored**; Studio reacts via [`on_server_connected`](08.02-callbacks.md) ([§8.2.7](08.02-callbacks.md)).

**Plugin behaviour.** Connect to the regional cloud MQTT broker using the logged-in user’s credentials (wire: [§6.2](06.02-mqtt.md)). On success / failure / session expiry, fire `on_server_connected` with the stock `(return_code, reason_code)` pair. Do not require Studio to poll `is_server_connected` before the callback.

**Return.** `0` on success; non-zero `BAMBU_NETWORK_ERR_*` on failure (Studio does not check it on this call site).

#### 8.3.4. `bambu_network_is_server_connected`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |

**Purpose.** Query whether the cloud MQTT session is currently up.

**Studio.** Used as a gate across the UI: `MachineObject::is_connected` for non-LAN printers ([DeviceManager.cpp:2354-2369](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.cpp#L2354-L2369)), Monitor / Calibration disconnect offsets, SelectMachine / SendToPrinter / SyncAms “connecting server” status, and Filament Manager cloud-write checks (`login && is_server_connected`).

**Plugin behaviour.** Return whether the cloud broker session is live. Must stay consistent with `on_server_connected` outcomes.

**Return.** `bool` — `true` if connected.

#### 8.3.5. `bambu_network_refresh_connection`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |

**Purpose.** Periodic keepalive / reconnect nudge for the cloud MQTT session.

**Studio.** [`DeviceManagerRefresher::on_timer`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L974-L1006) (~1 s) calls it when a selected machine exists and `is_user_login()`. Return is swallowed in an empty `try/catch`. The same tick may also call `install_device_cert` ([§8.4.7](08.04-lan.md) / [§10.2](10.02-secrets.md)).

**Plugin behaviour.** Refresh or reconnect the cloud session as needed. Safe to call frequently; should be cheap when already connected.

Evidence: stock `02.08.01.53` via `gap_probe` after a successful `connect_server` (`is_server_connected == true`): three back-to-back `refresh_connection` calls each returned `0` and produced **no** MQTT or HTTPS traffic on the wire (tcpdump on broker `:8883` + mitmproxy for HTTPS). Treat as a no-op keepalive hook when the session is already up; reconnect behaviour when disconnected was not re-probed here.

**Return.** `0` on success; non-zero on failure (Studio ignores).

#### 8.3.6. `bambu_network_start_subscribe`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `module` | `std::string` | Subscribe module hint (Studio often `"app"`). |

**Purpose.** Start a named subscription **module** on the cloud MQTT session.

**Studio.** Idle focus handler ([GUI_App.cpp:3504-3514](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L3504-L3514)) passes `module = "app"` when Studio becomes active; also tracks `mqtt_active`. Return unused.

**Plugin behaviour.** Enable the module-scoped cloud subscribe set for `"app"` (stock’s only observed module string). Device report topics are managed separately via `add_subscribe` / selection ([§6.2](06.02-mqtt.md)).

Evidence: stock `02.08.01.53` via `gap_probe` on a connected cloud session: `start_subscribe("app")` returned `0`; tcpdump on `us.mqtt.bambulab.com:8883` showed **no** MQTT `SUBSCRIBE` (or any application-data) after the initial CONNECT/CONNACK window. No `on_message` / `on_user_message` callbacks fired during the settle. Stock either applies `"app"` as a local module flag only, or the subscribe set is already active from `connect_server` with no incremental wire change.

**Return.** `0` on success; non-zero on failure (Studio ignores).

#### 8.3.7. `bambu_network_stop_subscribe`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `module` | `std::string` | Subscribe module hint (Studio often `"app"`). |

**Purpose.** Stop a named subscription module.

**Studio.** Same idle handler ([GUI_App.cpp:3515-3521](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L3515-L3521)) with `"app"` when Studio becomes inactive; tracks `mqtt_inactive`.

**Plugin behaviour.** Tear down the module-scoped subscriptions for the given module string. Cloud socket may stay up; this is not a full `disconnect`.

Evidence: paired with the `start_subscribe` probe above — `stop_subscribe("app")` returned `0` with **no** MQTT `UNSUBSCRIBE` / application-data on the broker socket; session stayed connected (`is_server_connected` remained true). Local module flag only on this plugin build when already connected.

**Return.** `0` on success; non-zero on failure (Studio ignores).

#### 8.3.8. `bambu_network_add_subscribe`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_list` | `std::vector<std::string>` | Device serials to add/remove from cloud report subscribe set. |

**Purpose.** Request cloud report subscriptions for a list of device ids.

**Studio.** Live path is [`DeviceManager::subscribe_device_list`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L673-L700) (multi-machine pages + resubscribe after `on_server_connected` when multi-machine is on and cache is non-empty — [GUI_App.cpp:2120-2125](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2120-L2125)). Helper `add_user_subscribe` ([DevManager.cpp:648-657](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L648-L657)) still exists, but its former GUI_App caller is **commented out**. Return unused.

**Plugin behaviour.** Accept a vector of `dev_id` strings; buffer them and apply cloud `device/<id>/report` (and related) subscriptions on the next successful cloud `CONNACK` if not already connected ([§6.2](06.02-mqtt.md) LAN-priority policy still applies). On subscribe failure, fire `on_subscribe_failure` ([§8.2.10](08.02-callbacks.md)).

**Return.** `0` on success; non-zero on failure (Studio ignores).

#### 8.3.9. `bambu_network_del_subscribe`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_list` | `std::vector<std::string>` | Device serials to add/remove from cloud report subscribe set. |

**Purpose.** Drop cloud report subscriptions for a list of device ids.

**Studio.** Called from `subscribe_device_list` with the computed unsub list before adding the new cache ([DevManager.cpp:697-698](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L697-L698)). `del_user_subscribe` has no live callers on the current pin. Return unused.

**Note (Studio quirk):** `subscribe_device_list` clears `subscribe_list_cache` before iterating it to build `unsub_list`, so the unsub vector built from that loop is empty on this pin — only the subsequent `add_subscribe(subscribe_list_cache)` path is effective unless other callers pass a non-empty unsub list.

**Plugin behaviour.** Remove the listed `dev_id`s from the desired cloud subscribe set and unsubscribe on the wire when connected.

**Return.** `0` on success; non-zero on failure (Studio ignores).

#### 8.3.10. `bambu_network_send_message`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_id` | `std::string` | Printer serial / device id. |
| `json_str` | `std::string` | MQTT JSON payload to publish. |
| `qos` | `int` | MQTT QoS (0/1/2). |
| `flag` | `int` | `MessageFlag` bits ([§8.3.1](#831-common-contract--sequence)); Studio default `0`. |

**Purpose.** Publish an opaque JSON command envelope to a printer over the **cloud** MQTT channel.

**Studio.** [`MachineObject::cloud_publish_json`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.cpp#L2446-L2452) → `send_message(get_dev_id(), json_str, qos, flag)`. Router [`publish_json`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.cpp#L2428-L2443) sends LAN-mode printers through `send_message_to_printer` ([§8.4.5](08.04-lan.md)) instead. Defaults are `qos=0`, `flag=0` ([DeviceManager.hpp](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.hpp#L754-L756)); many commands pass `qos=1`. Studio builds the JSON; the plugin forwards it. Payload shapes: [§12](12-mqtt.md). Signing / encryption policy: [§10.3](10.03-mqtt-field-encryption.md) / [§10.4](10.04-mqtt-signing.md).

**Plugin behaviour.** Publish `json_str` on the cloud request topic for `dev_id` (wire: [§6.2](06.02-mqtt.md)). Honour `qos` / `flag` as stock would. Return a real error code on failure so command UI can react.

**Return.** `0` on success; non-zero `BAMBU_NETWORK_ERR_*` (e.g. `SEND_MSG_FAILED`) on failure — **propagated** to Studio callers unlike most other §8.3 `int` returns.

Hub: [§8](08-abi-main.md).
