### 6.6. Cloud REST API

HTTPS to **Bambu’s cloud** (`api.bambulab.com` / `.cn`, plus S3/OSS for uploads) — not a TCP service on the printer. The plugin and Studio use it for account and fleet features that sit beside the LAN channels in [§6](06-channels.md).

#### What it is for

| Area | Examples |
|------|----------|
| User session | Ticket / OAuth login, refresh token, profile |
| Printer inventory | List / bind / rename; plaintext `dev_access_code` for LAN unlock |
| Shared app credentials | Cert endpoint (app chain / CRL / key blob) for signing, `app_cert_install`, HTTP PoP |
| Cloud print | Project create, presigned upload, `POST /my/task` dispatch |
| Camera remote | `ttcode` / TUTK UID minting |
| Content / sync | User presets, Filament Manager, MakerWorld / Mall, tracking |

Per-symbol HTTP surfaces: [§8.5](08.05-auth.md)–[§8.15](08.15-filament.md). Print pipeline: [§11](11-print.md).

#### Does a LAN-Only printer need it?

**No for direct device control.** SSDP + access code from the printer screen + LAN MQTT / FTPS / `:6000` / RTSP is enough to discover the printer, open sessions, upload, and print locally.

Cloud REST **is** needed for: signing in, fetching access codes without the screen, cloud-dispatched print, shared app-cert fetch (stock secured path), remote TUTK camera, cloud history / MakerWorld, and plugin OTA manifests. A headless LAN-Only setup with a manually entered code never has to call `api.bambulab.*`.
