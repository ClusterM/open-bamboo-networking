### 8.5. Authentication and user

User login is OAuth/ticket-based: Studio obtains a short ticket from a browser flow, then drives `get_my_token` → `get_my_profile` → `change_user` through [`TicketLoginTask`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/HttpServer.cpp#L516-L570) / WebView script handlers ([GUI_App.cpp:5127-5142](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5127-L5142)). Typedefs live in [`NetworkAgent.hpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/NetworkAgent.hpp). Shared cloud **app** credentials for command signing / `app_cert_install` / HTTP PoP are separate — [§10.2](10.02-secrets.md). MakerWorld preference (`get_mw_user_preference`) is [§8.12](08.12-makerworld.md); bind pin-code (`ping_bind`) is [§8.6.4](08.06-bind.md).

#### 8.5.1. Common contract

**HTTP surface.** Paths below are relative to the regional API host from [Cloud HTTP transport](13-http-transport.md), under `user-service`. Auth for profile (and later REST) is `Authorization: Bearer <access_token>` with `Content-Type: application/json` where a body is sent. Studio parses JSON from `http_body` itself; the plugin does not fill a typed out-struct for token/profile.

**login_info for `change_user`.** After token + profile succeed, Studio builds ([HttpServer.cpp:543-553](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/HttpServer.cpp#L543-L553)):

```json
{
  "data": {
    "refresh_token": "<refreshToken>",
    "token": "<accessToken>",
    "expires_in": "<str>",
    "refresh_expires_in": "<str>",
    "user": {
      "uid": "<uidStr>",
      "name": "<name>",
      "account": "<email>",
      "avatar": "<url>"
    }
  }
}
```

WebView `user_login` may pass a differently shaped JSON blob via `change_user(j.dump())` — the plugin must accept Studio’s login_info and that WebView payload.

**Session persistence.** After a successful `change_user`, the plugin owns the session. Cold start / restart uses `is_user_login()` without re-running ticket HTTP. Studio then may call `connect_server` ([§8.3.3](08.03-cloud-mqtt.md)) from [`on_user_login_handle`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5350-L5385).

**Login sequence.**

1. Browser / OAuth produces short ticket `T` (~6 alphanumeric chars).
2. `get_my_token(T, …)` → token JSON in `http_body`.
3. `get_my_profile(accessToken, …)` → profile JSON.
4. Studio builds login_info → `change_user` → `is_user_login()` must be true.
5. `request_user_login` → privacy / track → `on_user_login_handle` → `connect_server` (+ presets / filament `enqueue_pull`).

**Plugin-internal token refresh.** No ABI — the plugin refreshes on its own when the access token nears expiry. Wire (Evidence: [§13](13-http-transport.md) / MITM + probe; same shape as the working refresh client):

- `POST /v1/user-service/user/refreshtoken`
- Headers: `Authorization: Bearer <access_token>` (and the usual client headers from [§13](13-http-transport.md)), `Content-Type: application/json`
- Body: `{"refreshToken":"<refresh_token>"}`
- Success response: same field set as ticket mint (`accessToken`, `refreshToken`, `expiresIn`, `refreshExpiresIn`, …)

Do **not** confuse with Studio’s localhost HTTP `/refresh_token` (Agora camera URL helper in `HttpServer.cpp`, unrelated to cloud auth).

**Quirks.**

- Export **`bambu_network_get_user_nickanme`** (misspelled) — required name.
- [`NetworkAgent.cpp:378-379`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/NetworkAgent.cpp#L378-L379): `get_my_token_ptr` is `dlsym`’d as `"bambu_network_get_my_token"` but cast to `func_get_my_profile` (same signature). Export **both** `get_my_token` and `get_my_profile`.
- `set_on_user_login_fn` is not registered by current Studio ([§8.2.11](08.02-callbacks.md)).

**Return convention.** HTTP helpers return `0` on success or `<0` on failure and fill `http_code` / `http_body`. Session mutators return `int` (Studio often ignores and gates on `is_user_login`). Getters return `std::string` (empty if logged out).

#### 8.5.2. `int bambu_network_get_my_token(void* agent, std::string ticket, unsigned int* http_code, std::string* http_body)`

**Purpose.** Exchange an OAuth ticket for access / refresh tokens.

**Studio.** [`TicketLoginTask::do_request_login_info`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/HttpServer.cpp#L516-L570) (also WebView `user_ticket_login` path). Fails if return `<0` or `http_body` empty; `http_code` is logged only. Studio parses the body as `TokenResp`.

**Plugin behaviour.** `POST /v1/user-service/user/ticket/<T>` with body `{"ticket":"<T>"}`. Evidence: SSLKEYLOGFILE / MITM. Write raw response into `*http_body` and HTTP status into `*http_code`.

Typical 200 OK:

```json
{
  "accessToken":    "AQB...",
  "refreshToken":   "AQB...",
  "expiresIn":      31536000,
  "refreshExpiresIn": 31536000,
  "tfaKey":         "",
  "accessMethod":   "ticket",
  "loginType":      "",
  "firstAppLogin":  false
}
```

`expiresIn` / `refreshExpiresIn` are 1 year (31 536 000 s) in observed data. On initial issue `accessToken` and `refreshToken` may be identical; they can diverge after refresh. Token format: `AQA…` / `AQB…` prefix, base64url opaque (~100+ chars).

**Return.** `0` on success; `<0` on transport / HTTP failure.

#### 8.5.3. `int bambu_network_get_my_profile(void* agent, std::string token, unsigned int* http_code, std::string* http_body)`

**Purpose.** Fetch the signed-in user’s profile for a bearer token.

**Studio.** Same `do_request_login_info` immediately after token success, with `token = accessToken`. Login path consumes only `uidStr`, `account`, `name`, `avatar` into login_info (not `nickname` on that path).

**Plugin behaviour.** `GET /v1/user-service/my/profile` with `Authorization: Bearer <token>`. Evidence: SSLKEYLOGFILE / MITM. Forward body into `*http_body`.

    "bio": "",

#### 8.5.4. `int bambu_network_change_user(void* agent, std::string user_info)`

**Purpose.** Apply a login session (tokens + user fields) into the agent.

**Studio.** After building login_info from ticket login ([HttpServer.cpp:368+](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/HttpServer.cpp)); WebView `user_login` / `user_ticket_login` ([GUI_App.cpp:5127-5142](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5127-L5142)). Return is ignored; success is `is_user_login() == true`.

**Plugin behaviour.** Parse `user_info` JSON, store access/refresh tokens and user identity, mark the session logged in. Do not require Studio to call `get_my_token` again on cold start if tokens were persisted. Clearing the session is **`user_logout`**, not `change_user("{}")` / empty string (those are no-ops on login state — see shapes below).

**Return.** `0` on success; non-zero on failure (Studio still checks `is_user_login`).

**Accepted `user_info` shapes** (Evidence: `plugin_runner --action gap_probe` vs stock `02.08.01.53`; each shape tested after `user_logout(false)` so a reject cannot leave a prior session looking accepted):

| Shape | `is_user_login` after | Notes |
|-------|----------------------|--------|
| Studio ticket `login_info` (`{"data":{"token","refresh_token","expires_in","refresh_expires_in","user":{…}}}`) | `true` | Canonical HttpServer path ([§8.5.1](#851-common-contract)) |
| Same object plus `"command":"user_login"` | `true` | WebView `handle_script_message` passes `j.dump()` including `command` |
| `{"data":{"token":"…"}}` only | `false` | Token alone is not enough — needs the `user` object (at least enough for stock to mark logged in) |
| Flat `{"access_token","refresh_token","user_id"}` (OBN on-disk style) | `false` | Stock does not accept this; runner converts OBN → Studio envelope before `change_user` |
| `{}` / `""` | `false` | Do **not** clear an existing session by themselves; use `user_logout` |

#### 8.5.5. `bool bambu_network_is_user_login(void* agent)`

**Purpose.** Query whether the agent has an active user session.

**Studio.** Wrapper `GUI_App::is_user_login` and dozens of UI gates (presets, print, filament cloud write, cold restore). Auth-critical checks after `change_user` and before logout.

**Plugin behaviour.** Return whether a usable session is present (in-memory and/or restored from config dir).

**Return.** `bool`.

#### 8.5.6. `std::string bambu_network_get_user_id(void* agent)`

**Purpose.** Return the logged-in user’s id string (`uidStr`).

**Studio.** Preset sync, design/export JSON, DeviceManager print metadata, sync guards — many call sites. Empty string means no user.

**Plugin behaviour.** Return cached `uid` / `uidStr` from the last successful login; `""` if logged out.

**Return.** `std::string`.

**Purpose.** Return the user’s display / account name.

**Studio.** BindDialog UnBind UI; DeviceManager bind-status strings.

**Plugin behaviour.** Return cached `name` (or account label Studio expects); `""` if logged out.

**Return.** `std::string`.

**Purpose.** Return the user’s avatar URL.

#### 8.5.10. `int bambu_network_get_user_info(void* agent, int* identifier)`

**Purpose.** Out-param accessor for a numeric `identifier` from the user profile.

**Studio.** Resolved and wrapped in `NetworkAgent`, but **no GUI call sites** on this pin. Cloud profile JSON still contains `"identifier"`.

**Plugin behaviour.** Export for ABI completeness. If called, write the cached identifier (e.g. from profile) into `*identifier`.

**Return.** `0` on success; non-zero on failure / not logged in.

#### 8.5.11. `std::string bambu_network_build_login_cmd(void* agent)`

**Purpose.** Build the JSON string Studio injects into the homepage WebView to show the logged-in avatar / name.

**Studio.** [`GUI_App::get_login_info`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L4618-L4635): when `is_user_login()`, `build_login_cmd()` → `window.postMessage(<cmd>)` via `run_script_left`. Homepage WebView JS dispatches on `command` ([`left.js`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/resources/web/homepage3/js/left.js#L35-L43); also [`login.js`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/resources/web/login/js/login.js#L21-L24)): for `studio_userlogin` it reads `data.avatar` and `data.name` only.

**Plugin behaviour.** Return a JSON object (not a JS string literal — Studio wraps it in `postMessage(%s)`) that at minimum matches:

```json
{
  "sequence_id": "0",
  "command": "studio_userlogin",
  "data": {
    "avatar": "<url>",
    "name": "<display name>"
  }
}
```

Evidence: Studio WebView handlers above (required `command` + `data.avatar` / `data.name`). Extra `data` fields are harmless if present; stock may emit more. This is **not** cloud HTTP — the string is built locally from the plugin session cache.

**Return.** `std::string` (JSON text).

#### 8.5.12. `std::string bambu_network_build_logout_cmd(void* agent)`

**Purpose.** Mirror of `build_login_cmd` for the logged-out homepage state.

**Studio.** Same `get_login_info`: when **not** logged in, Studio calls `user_logout()` (default `request=false`) then `build_logout_cmd()` → `postMessage` ([GUI_App.cpp:4626-4631](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L4626-L4631)). WebView handlers for `studio_useroffline` clear the avatar UI and do not read `data` ([`left.js`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/resources/web/homepage3/js/left.js#L45-L52)).

**Plugin behaviour.** Return JSON with `"command":"studio_useroffline"` (empty `data` is fine). Local only — not a cloud revoke.

**Return.** `std::string` (JSON text).

#### 8.5.13. `std::string bambu_network_build_login_info(void* agent)`

**Purpose.** Build a login-info string for WebView panels.

**Studio.** `WebViewPanel::SendLoginInfo` wraps the ABI; **no live callers** of that wrapper on this pin.

**Plugin behaviour.** Still export. Return the same JSON as `build_login_cmd` while a session is present.

Evidence: stock `02.08.01.53` via `gap_probe` — both return identical:

```json
{
  "command": "studio_userlogin",
  "data": {
    "avatar": "<url>",
    "name": "<display name>"
  },
  "sequence_id": "10001"
}
```

`build_logout_cmd` (for contrast): `{"command":"studio_useroffline","sequence_id":"10001"}`. After `user_logout(true)`, `is_user_login` is false but stock may still return the previous `studio_userlogin` string from `build_login_cmd` / `build_login_info` (profile cache not wiped); Studio’s logged-out homepage path uses `build_logout_cmd` instead.

**Return.** `std::string`.

#### 8.5.14. `int bambu_network_user_logout(void* agent, bool request)`

**Purpose.** Clear the plugin-owned session. The `request` flag is Studio’s hint that a server-side revoke may be appropriate.

**Studio.** [`request_user_logout`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L4684-L4718) → `user_logout(true)` (homepage logout, Preferences region change, HTTP 401 / expired-login paths, etc.). Other paths call `user_logout()` / `user_logout(false)` (privacy cancel, region guide, and the not-logged-in branch of `get_login_info`). Studio then clears presets, cookies, devices, and filament cloud queues itself. Return ignored. Studio does **not** call cloud logout HTTP itself — any revoke is inside the plugin when `request` is true.

**Plugin behaviour.** Always drop tokens / user cache and make `is_user_login()` false. When `request` is false: local clear only (no cloud call). When `request` is true, stock also revokes on the cloud (Evidence: MITM, Studio AppImage `02.08.01.55` + agent `02.08.01.53`):

- `POST /v1/user-service/my/logout`
- Headers: `Authorization: Bearer <access_token>`, `Content-Type: application/json`, plus the usual `X-BBL-*` / `User-Agent: bambu_network_agent/…` set from [§13](13-http-transport.md)
- Body: `{"refreshtoken":""}` (lowercase key)
- Response: `200` with empty body

Note the body key is **`refreshtoken`** (all lowercase), not `refreshToken`.

Evidence (follow-up): `gap_probe --do-logout` after `change_user` with a **non-empty** `data.refresh_token` still POSTed `{"refreshtoken":""}` — stock does not copy the refresh token into the logout body; Bearer access token is sufficient. No capture has shown a non-empty `refreshtoken` field from this plugin version.

**Return.** `0` on success; non-zero on failure.
