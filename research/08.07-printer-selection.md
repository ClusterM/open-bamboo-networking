#### `get_user_selected_machine` / `set_user_selected_machine`

`set_user_selected_machine` is the **cloud-mode** counterpart of `connect_printer` ([§8.4](08.04-lan.md)): selecting a cloud machine calls it with the serial, leaving one calls it with `""`. The return value is ignored.

`get_user_selected_machine` is only read back at startup, and it is the plugin's answer that decides whether the Device tab comes up selected. Both slicers keep their own copy in `app_config["user_last_selected_machine"]` and consult the plugin only when that copy is empty ([`DeviceManager::get_user_last_machine`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L893-L905), [Orca L944-L956](https://github.com/OrcaSlicer/OrcaSlicer/blob/7eaff76cecd1412182efbd0106dcbc41f4e8de43/src/slic3r/GUI/DeviceCore/DevManager.cpp#L944-L956)) — but both also write that copy from every selection change, including deselection ([`set_selected_machine` tail](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L626)).

**Studio.** [`load_last_machine`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L907-L920) selects the only cloud machine outright when `userMachineList.size() == 1` and never asks anyone; with several machines it prefers the remembered id and falls back to the first one. A single-printer account therefore looks like it remembers the selection even when the plugin answers `""`.

**Orca.** [`load_last_machine`](https://github.com/OrcaSlicer/OrcaSlicer/blob/7eaff76cecd1412182efbd0106dcbc41f4e8de43/src/slic3r/GUI/DeviceCore/DevManager.cpp#L958-L969) dropped both fallbacks in Aug 2026: no match in `userMachineList` means nothing is selected. And [`set_live_printer_agent`](https://github.com/OrcaSlicer/OrcaSlicer/blob/7eaff76cecd1412182efbd0106dcbc41f4e8de43/src/slic3r/GUI/GUI_App.cpp#L3940-L3964), which runs while installing the printer agent at startup, deselects through both channels — `set_selected_machine("")`, which persists an empty `user_last_selected_machine`, and a direct `set_user_selected_machine("")` on the agent — about a second before discovery or the cloud device list produce any printer. So on Orca the plugin's copy is the *only* surviving one, and it must not be thrown away by the deselect that immediately precedes the query (GitHub issue [#78](https://github.com/ClusterM/open-bambu-networking/issues/78)).

**Plugin.** OBN persists the last **non-empty** id to `<config_dir>/obn.state.json` and answers `get_user_selected_machine` from the live selection, falling back to that file while the slicer has not selected anything in this session. Deselection is deliberately not persisted: besides the startup path above, Orca clears the selection on logout, from the calibration panel and from `DeviceManagerRefresher::on_timer` whenever the printer is momentarily absent. The remembered id never starts a LAN session on its own — only a selection made in this session does ([STATUS](../STATUS.md), "Always-on LAN for the selected printer").

`get_printer_firmware` is invoked from `MachineObject::get_firmware_info` ([DeviceManager.cpp:3988](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.cpp#L3988)) on a background thread when the user opens **Device → Update**. A return value `< 0` makes Studio silently hide the firmware list (`m_firmware_valid = false`). Otherwise `http_body` is parsed as JSON with the following schema:

```json
{
  "devices": [{
    "dev_id": "<printer serial>",
    "version": "<currently installed firmware version>",
    "firmware": [
      {
        "version": "01.08.02.00",
        "force_update": false,
        "url": "https://public-cdn.bblmw.com/upgrade/device/<model>/<version>/product/<hash>/ota-<filename>.json.sig",
        "description": "optional release notes text (plain/markdown)",
        "status": "release"
      }
    ],
    "ams": [{
      "firmware": [
        { "version": "00.00.07.89", "force_update": false, "url": "https://.../ams.bin", "description": "...", "status": "release" }
      ]
    }]
  }]
}
```

OTA URL format: `https://public-cdn.bblmw.com/upgrade/device/<model-id>/<version>/product/<hash>/ota-<model>_v<version>-<timestamp>.json.sig`. `force_update: true` indicates the printer should refuse to operate until this firmware is applied — Studio greys out all controls and shows only the Update button. `status` is `"release"` for GA firmware or `"beta"` for beta-channel builds (controlled by the `isFirmwareBetaOpen` flag in `GET /v1/user-service/my/profile` → `setting.isFirmwareBetaOpen`). The `version` field at the device level is the currently installed version, not present in the pre-capture schema — Studio derives installed version from MQTT `info.command=get_version` regardless.

Studio creates a `FirmwareInfo item` per entry in `firmware[]` / `ams[].firmware[]` and derives the file name from the tail of `url` (`item.name = url.substr(url.find_last_of('/') + 1)`). If the name cannot be extracted, the entry is skipped. The `description` field is the text displayed in the **Release Notes** dialog.

Important: Studio does **not** read the currently installed version from this response — that arrives separately, through the MQTT `info.command=get_version` payload (array `info.module[]`, field `sw_ver`) and `push_status.upgrade_state.new_ver_list`. This ABI call answers only "what can be flashed" (plus, optionally, release notes for those versions). The **Update** button ultimately publishes `{"upgrade":{"command":"upgrade_confirm"}}` over LAN MQTT — the printer itself downloads the firmware from the CDN, and Studio uses the URL in `firmware[].url` only for the displayed file name.

When `devices[0].firmware[]` is empty (the currently installed firmware is already the newest one known to the printer), the Release Notes dialog opens empty — this is normal stock behaviour, not a bug.
