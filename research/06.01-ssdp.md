### 6.1. SSDP discovery

Printers announce themselves on the LAN with HTTP-style **SSDP `NOTIFY`** datagrams so clients can learn **serial (`dev_id`)** and **LAN IP** without a prior cloud lookup.

#### Wire (captured 2026-07, P2S/N7-class)

| Fact | Observation |
|------|-------------|
| UDP destination | **`255.255.255.255:2021`** (and/or local broadcast); listeners bind **`:2021`** |
| Source port | **2021** |
| Period | about **5 s** between NOTIFYs |
| `Host:` header | `239.255.255.250:1990` — classic SSDP Host string; **not** the UDP port that carries the packet |

Older docs that said “listen on `239.255.255.250:1990`” confused the Host header with the socket. Stock/OBN discovery that works on current firmware listens on **UDP 2021**.

#### Sample `NOTIFY` (live)

```http
NOTIFY * HTTP/1.1
Host: 239.255.255.250:1990
Server: UPnP/1.0
Location: 10.13.1.30
NT: urn:bambulab-com:device:3dprinter:1
NTS: ssdp:alive
USN: 22E8BJ610801473
Cache-Control: max-age=1800
DevModel.bambu.com: N7
DevName.bambu.com: 3Д принтерик
DevConnect.bambu.com: cloud
DevBind.bambu.com: occupied
Devseclink.bambu.com: secure
DevInf.bambu.com: wlan0
DevVersion.bambu.com: 01.02.00.00
DevCap.bambu.com: 1
```

#### Header fields

| Header | Meaning |
|--------|---------|
| Start line | `NOTIFY * HTTP/1.1` (alive announcement) |
| `Host` | SSDP multicast host form (`239.255.255.250:1990`); informational |
| `Server` | e.g. `UPnP/1.0` |
| `Location` | Printer **LAN IPv4** (no URL scheme in observed packets) |
| `NT` / `NTS` | Notification type / subtype (`urn:bambulab-com:device:3dprinter:1`, `ssdp:alive`) |
| `USN` | Device serial / `dev_id` (same string used as MQTT topic id) |
| `Cache-Control` | `max-age=…` (advertised cache hint; clients typically refresh on every NOTIFY) |
| `DevModel.bambu.com` | Model family token (e.g. `N7`) → Studio `dev_type` |
| `DevName.bambu.com` | User-visible name (UTF-8) → `dev_name` |
| `DevConnect.bambu.com` | Mode chosen in the **printer UI** — whether **LAN-Only** is on (`lan`) or the printer is in the normal cloud-connected mode (`cloud`, …). Not “is reachable on LAN”. Studio maps this to `connect_type` / `is_lan_mode_printer()` ([§11.1](11.01-studio-orchestration.md)) |
| `DevBind.bambu.com` | Bind occupancy (`occupied`, …) → `bind_state` |
| `Devseclink.bambu.com` | Security-link flag (`secure`, …) → `sec_link` |
| `DevInf.bambu.com` | Interface / connection name (`wlan0`, …) → `connection_name` |
| `DevVersion.bambu.com` | Firmware / SSDP schema version string → `ssdp_version` |
| `DevCap.bambu.com` | Capability integer (observed `1`); not mapped by all clients |

Studio’s `on_machine_alive` JSON expects keys such as `dev_id`, `dev_ip`, `dev_type`, `dev_name`, `connect_type`, `bind_state`, `sec_link`, `ssdp_version`, `connection_name` (plus empty `dev_signal` if unused). ABI: `bambu_network_start_discovery` / `set_on_ssdp_msg_fn` — [§8.4](08.04-lan.md).
