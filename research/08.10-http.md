#### 8.10.1. What each ABI call does behind the curtain

All paths below are relative to the regional API host from [Cloud HTTP transport](13-http-transport.md). The "evidence" column states how firm the mapping is — either `MITM` (seen in a live dump of the stock plugin), `probe` (issued by hand with `curl` against production), `source` (read out of Studio's own code) or `stub` (the plugin never hits the network and Studio is happy with a canned response).

- **`get_studio_info_url`** — string accessor, **no HTTP**. Stock `02.08.01.53` returns `https://api.bambulab.com/v1/iot-service/api/slicer/resource` (CN host when region is CN). Early Studio (`GUI_App` / `PresetUpdater`) appended query params for news/banner / updater; **[BambuStudio `ba049f6a2`](https://github.com/bambulab/BambuStudio/commit/ba049f6a2e08c3b6033660bb84da80c08722974b) has no GUI call sites** (symbol still `dlsym`'d). *Evidence: `plugin_runner --action http_probe` + source (historical).*
- **`set_extra_http_header`** — pure state update. Studio calls it during startup and on region/language switches to attach fingerprint headers to every subsequent request. The stock plugin stores the map and folds it into outgoing header sets; the server ignores the contents. *Evidence: source.*
- **`get_my_message`** — Message Centre inbox poll for `(type, after, limit)`. **Studio callers:** ABI added `497be311d`; **no GUI call site through [BambuStudio `ba049f6a2`](https://github.com/bambulab/BambuStudio/commit/ba049f6a2e08c3b6033660bb84da80c08722974b)** (NetworkAgent wrappers only). Stock `02.08.01.53` issues `GET /v1/user-service/my/messages/type=<t>&after=<a>&limit=<n>` (path uses `/` before the param list — **not** `?type=…`); production answered **404** `"404 page not found"` for `type=0`. ABI returns `rc!=0`, `http_code=404`. *Evidence: MITM via `http_probe`.*
- **`check_user_task_report`** — would decide whether to show a "rate this print" prompt. **Studio callers:** NetworkAgent wrappers only — **no GUI call site through [BambuStudio `ba049f6a2`](https://github.com/bambulab/BambuStudio/commit/ba049f6a2e08c3b6033660bb84da80c08722974b)**. Stock probe (`http_probe`, logged-in session, nothing pending): **no dedicated HTTPS** between the call and return; outs were `task_id=-1`, `printable=true`, `rc=0`. Endpoint for a non-empty report queue remains unconfirmed. *Evidence: MITM via `http_probe`.*
- **`get_user_print_info`** — Two confirmed endpoints serve this data:
  - `GET /v1/iot-service/api/user/bind` — returns `{ "devices":[{ "dev_id", "name", "online", "print_status", "dev_model_name", "dev_product_name", "dev_access_code", "print_job", "nozzle_diameter", "dev_structure", ... }]}`. Uses `name`/`online`/`print_status` — requires remapping to Studio's expected `dev_name`/`dev_online`/`task_status`. *Evidence: MITM + probe.*
  - `GET /v1/iot-service/api/user/print?force=true` — returns `{ "devices":[{ "dev_id", "dev_name", "dev_model_name", "dev_product_name", "dev_online", "dev_access_code" }]}`. Field names match Studio's parser directly; no remapping needed. Also polled repeatedly by the stock plugin as a cloud print-job queue check (returns `{"message":"success","code":0,"error":null}` with no `devices` key when the queue is empty). *Evidence: SSLKEYLOGFILE capture.*
  - **Security note:** `dev_access_code` is returned in plaintext by both endpoints — see [§10.6](10.06-lan-tls-and-access-codes.md).
- **`get_user_tasks`** — Cloud Task / History grid (`TaskManager`, Print History WebView). Stock: `GET /v1/user-service/my/tasks?limit=&offset=&status=[&deviceId=]` with Bearer auth. Response `{ "total": N, "hits":[{ "id", "title", "deviceId", "deviceName", "cover", "status", "startTime", "endTime", "profileId", "designId", "designTitle", "mode", ... }] }` is passed through to Studio's JSON parser unchanged. *Evidence: MITM of stock `bambu_network_agent/02.08.01.51`.*
- **`get_task_plate_index`** — looks up which plate a given cloud task/subtask id ran on. **Studio callers (legacy):** early `DeviceManager::update_slice_info` when `plate_idx < 0`. **[BambuStudio `ba049f6a2`](https://github.com/bambulab/BambuStudio/commit/ba049f6a2e08c3b6033660bb84da80c08722974b):** removed; plate comes from `push_status` / `get_subtask_info` `content.info.plate_idx`. Stock: **same URL as `get_subtask_info`** — `GET /v1/iot-service/api/user/task/<id>` — and returns `*plate_index` from `content.info.plate_idx` (probe: id `1114566547` → plate `1`). *Evidence: MITM via `http_probe` + source (historical).*
- **`get_subtask_info`** — Device-panel cover / plate metadata for the active print. Stock: `GET /v1/iot-service/api/user/task/<subtask_id>` (Bearer, `User-Agent: bambu_network_agent/…`). Studio pulls the printer-card hero image from `context.plates[<plate_idx>].thumbnail.url`; `content` is a JSON *string* holding an inner `{info:{plate_idx}}` envelope (`DeviceManager::update_slice_info`). The same `plates[]` entries also carry `prediction`, `weight`, `filaments[]` (what legacy `get_slice_info` used to supply). Studio then downloads the PNG itself via wxWebRequest. *Evidence: MITM stock `02.08.01.53` (Device tab + `http_probe`) + Studio source.*
- **`get_slice_info`** — slice summary for a cloud project/profile/plate. **Studio callers (legacy):** early `update_slice_info` after `get_task_plate_index`; replaced by **`get_subtask_info`** (`98a7a10ce` / `16cee3299`); **no GUI call site through [BambuStudio `ba049f6a2`](https://github.com/bambulab/BambuStudio/commit/ba049f6a2e08c3b6033660bb84da80c08722974b)**. Stock: `GET /v1/iot-service/api/user/project/<project_id>?profile_id=<profile_id>` (plate index is **not** in the URL). Empty `project_id` → `…/project/?profile_id=…` **405**; `model_id` as project → **422**; wrong id → **403/400**. Successful body shape was never captured (cloud tasks in the probe had empty `project_id`). *Evidence: MITM via `http_probe` + source (historical).*
- **`report_consent`** — cloud consent telemetry. **Studio callers ([`ba049f6a2`](https://github.com/bambulab/BambuStudio/commit/ba049f6a2e08c3b6033660bb84da80c08722974b)):** `GUI_App::report_consent_common` (startup / privacy history / Privacy Policy Update), `HelioStatementDialog::report_consent_install`, `ExpandCenterDialog::report_consent_unstall`. If the user is logged in → `NetworkAgent::report_consent(body)`; else Studio itself `POST`s the same body to `v1/user-service/user/consent` (`GUI_App::report_consent`). The ABI argument is the **entire JSON body** (misnamed `expand`), e.g. `{"consentBody":"{\"version\":1,\"scene\":\"studio_improvement_policy_enable\",\"formList\":[{\"formID\":\"StudioImprovementPolicy\",\"op\":\"Opt-in\"}]}"}` (`op` is `Opt-in` / `Withdraw`; CN appends `-CN` to `formID`). Scenes include `studio_improvement_policy_enable`, `studio_privacy_policy_enable`, `helio_enable`. Studio ignores the return value; local `app_config` already records the choice. *Evidence: Studio source (URL + body); stock plugin wire assumed same endpoint when logged in.*
