#### 8.10.1. Common contract

**`TaskQueryParams`** ([bambu_networking.hpp:252-258](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/bambu_networking.hpp#L252-L258)) — by-value argument of `get_user_tasks`:

| Field | Type | Default | Wire (`GET …/my/tasks`) | Meaning |
| --- | --- | --- | --- | --- |
| `dev_id` | `std::string` | — | `deviceId` when non-empty | Filter tasks for one printer; omit query key when empty |
| `status` | `int` | `0` | `status` | Cloud task-status filter (Studio / WebView pass-through; `0` = unrestricted / “all” in observed callers) |
| `offset` | `int` | `0` | `offset` | Pagination offset |
| `limit` | `int` | `20` | `limit` | Page size |

**Shared transport.** Paths below are relative to the regional API host from [§6.6 Cloud REST API](06.06-cloud-rest.md). Auth is the usual `Authorization: Bearer <access_token>` unless noted. Many symbols write raw HTTP status into `unsigned int* http_code` and/or the response body into `std::string* http_body` / `task_json` / `slice_json` — Studio parses JSON itself.

**Evidence tags** (used on each symbol):

| Tag | Meaning |
| --- | --- |
| `MITM` | Seen in a live dump of the stock plugin |
| `probe` | Issued by hand (`curl` / `plugin_runner --action http_probe`) against production |
| `source` | Read out of Studio’s own code |
| `stub` | Plugin never hits the network; Studio accepts a canned response |

**Return convention.** Most symbols return `int`: `0` on success, non-zero on failure. `get_studio_info_url` returns a URL string. There is no dedicated `BAMBU_NETWORK_ERR_*_HTTP_*` family for this surface in [§8.16](08.16-errors.md) beyond generic codes where Studio cares.

#### 8.10.4. `bambu_network_get_user_print_info`

**Studio.** [`DeviceManager`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L878) (and related refresh paths) via [NetworkAgent.cpp:1315-1322](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/NetworkAgent.cpp#L1315-L1322).

**Plugin behaviour.** Two confirmed endpoints serve this data (stock has been observed on both):

1. `GET /v1/iot-service/api/user/bind` — `{ "devices":[{ "dev_id", "name", "online", "print_status", "dev_model_name", "dev_product_name", "dev_access_code", "print_job", "nozzle_diameter", "dev_structure", … }]}`. Field names match Studio’s parser directly. Also polled as a cloud print-job queue check (empty queue → `{"message":"success","code":0,"error":null}` with no `devices` key). Evidence: SSLKEYLOGFILE capture.

**Security note:** `dev_access_code` is returned in plaintext by both endpoints — see [§10.6](10.06-lan-tls-and-access-codes.md). Write status / body into the out-params.

**Return.** `0` on success; non-zero on failure.

#### 8.10.8. `bambu_network_get_slice_info`

**Parameters.**

| Name | Type | Meaning |

| `plate_index` | `int` | Plate index (Studio arg; **not** placed in the stock URL). |
| `slice_json` | `std::string*` | out: slice summary JSON. |

**Purpose.** Fetch slice summary for a cloud project/profile/plate.

**Studio.** Legacy: early `update_slice_info` after `get_task_plate_index`; replaced by **`get_subtask_info`** (`98a7a10ce` / `16cee3299`). **No GUI call site through [BambuStudio `ba049f6a2`](https://github.com/bambulab/BambuStudio/commit/ba049f6a2e08c3b6033660bb84da80c08722974b).**

**Plugin behaviour.** Stock: `GET /v1/iot-service/api/user/project/<project_id>?profile_id=<profile_id>` (Bearer; `plate_index` is **not** in the URL). Empty `project_id` → `…/project/?profile_id=…` **405**; `model_id` as project → **422**; wrong / foreign id → **403/400**. On success the HTTP body is the full project envelope (`project_id`, `model_id`, `profiles[]`, …); stock then picks `profiles[*].context.plates[]` with `index == plate_index` and writes that **plate object** into `*slice_json` as pretty-printed JSON (`indent=4`, keys sorted alphabetically). Example plate fields (stock `02.08.01.53` via `http_probe`, project from a prior cloud print):

```json
{
    "filaments": [
        {
            "color": "#E06640",
            "filament_id": "Pd4a7530",
            "id": "1",
            "type": "PLA",
            "used_for_object": true,
            "used_for_support": false,
            "used_g": "18.64",
            "used_m": "6.25"
        }
    ],
    "gcode": { "bucket": "", "dir": "", "name": "", "url": "" },
    "index": 1,
    "prediction": 2160,
    "thumbnail": { "bucket": "or-cloud-model-prod", "dir": "Metadata", "name": "plate_1.png", "url": "https://…/plate_1.png?…" },
    "weight": 18.64
}
```

(Other plate keys also present: `top_picture` / `pick_picture` / `no_light_picture`, `objects`, `warning`, `layer_filament_lists`, ….) Legacy Studio parsers only needed `prediction` / `weight` / `thumbnail` / `filaments[]` (`color`, `type`, `used_g`, `used_m`). Print-history / `get_subtask_info` tasks often have empty `project_id` — those cannot drive this call; a real id comes from the cloud print pipeline (`POST …/user/project`). Evidence: MITM `stock_http_probe_slice.mitm` + `http_probe` (success) / earlier error probes + source (historical).
