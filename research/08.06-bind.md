#### 8.6.1. Common contract

**Return convention.** All symbols return `int`: `0` / `BAMBU_NETWORK_SUCCESS` on success, else `BAMBU_NETWORK_ERR_*` ([§8.16](08.16-errors.md)) — e.g. `BIND_FAILED` (−5), `UNBIND_FAILED` (−6), `QUERY_BIND_INFO_FAILED` (−12), and the bind-stage codes `−1010`…`−1090` (socket / ticket / login-report). Studio often gates UX on `result < 0` and on `OnUpdateStatusFn` `code` for `bind`.

**Three cloud ticket / pin surfaces** (do not mix them):

| Surface | Path | Used by |
|---------|------|---------|
| Web SSO mint | `GET /v1/user-service/user/ticket` then `POST /v1/user-service/my/ticket/<T>` | `request_bind_ticket` (§8.6.6) |
| Device ticket validate / account-bind | `GET` + `POST /v1/user-service/my/ticket/<T>` (`source":"device"`) | `bind` (§8.6.3) |
| Pin-code bind | `POST /v1/user-service/my/pincode/<PIN>` | `ping_bind` (§8.6.4) |

**`detectResult`** ([bambu_networking.hpp:187-196](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/bambu_networking.hpp#L187-L196)) — out-param of `bind_detect`:

| Field | Type | Meaning |
| --- | --- | --- |
| `result_msg` | `std::string` | Human / diagnostic string from the probe. **Unused** by Studio call sites on this pin. |
| `command` | `std::string` | Echo / command tag from the `:3000` reply. **Unused** by Studio on this pin. |
| `dev_id` | `std::string` | Printer serial |
| `model_id` | `std::string` | Printer model id |
| `dev_name` | `std::string` | Display name |
| `version` | `std::string` | Firmware / product version string |
| `bind_state` | `std::string` | e.g. `free` / `occupied` |
| `connect_type` | `std::string` | e.g. `lan` / `cloud` / `farm` |

Typical gates: reject `bind_state == "occupied"` unless `connect_type == "farm"`; reject `connect_type == "cloud"` for LAN-only insert. SSDP field mapping: [§6.1](06.01-ssdp.md).

**`BindJobStage`** ([bambu_networking.hpp:172-179](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/bambu_networking.hpp#L172-L179)) — `status` argument of `OnUpdateStatusFn` during `bind`. [`BindJob`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/Jobs/BindJob.cpp#L81-L98) maps each value to a progress percent (all share the same “Logging in” copy):

| Value | Enumerator | Studio progress |
| ---: | --- | ---: |
| `0` | `LoginStageConnect` | 15% |
| `1` | `LoginStageLogin` | 30% |
| `2` | `LoginStageWaitForLogin` | 45% |
| `3` | `LoginStageGetIdentify` | 60% |
| `4` | `LoginStageWaitAuth` | 80% |
| `5` | `LoginStageFinished` | 100% |

**Lifecycle (Studio-driven).**

1. **LAN detect / restore** — `bind_detect(ip, "secure")` → fill `detectResult` → `insert_local_device` (no account bind). Call sites: [`GUI_App` `sLocalBindFunc`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L8468-L8505), [`DevManager`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L367-L414), [`InputIpAddressDialog`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/ReleaseNote.cpp#L2034-L2097).
2. **Account bind** — SSDP `MachineObject` → Bind UI → [`BindJob`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/Jobs/BindJob.cpp#L57-L145) → `bind(...)` with `OnUpdateStatusFn` stages `BindJobStage` above. Success → refresh user machine list / subscribe.
3. **Pin bind** — [`PingCodeBindDialog`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/BindDialog.cpp#L311-L330) → `ping_bind(6-char)`.
4. **Unbind** — UnBind dialog → [`request_user_unbind`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L4730-L4738) → `unbind(dev_id)`.
5. **Web SSO** — MakerWorld / Print History / external browser → `request_bind_ticket` → navigate `…/api/sign-in/ticket?to=…&ticket=…`.

Pre-02.08 plugins omit the `dev_model` argument on `bind`; ABI ≥ 02.08 matches the table above.

#### 8.6.2. `bambu_network_bind_detect`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_ip` | `std::string` | Printer LAN IPv4. |
| `sec_link` | `std::string` | Security link mode (Studio restore uses `"secure"`). |
| `detect` | `detectResult&` | out: filled `detectResult` from TCP `:3000` detect. |

**Purpose.** Resolve LAN printer identity / bind state at `dev_ip` into a `detectResult` (before inserting a local device).

**Studio.** Always passes `sec_link = "secure"`. Return `< 0` aborts insert / shows IP errors (`-1` connect, `-2` publish login, `-3` used on Apple skip path in Input IP dialog). Success → gate on `bind_state` / `connect_type`, then `insert_local_device`. **Not** called from `BindMachineDialog` / `BindJob` (account bind uses SSDP `MachineObject`).

**Plugin behaviour.** LAN-only — no cloud bind/pincode/ticket HTTPS (Evidence: MITM `stock_bind_detect.mitm`). Stock opens **plaintext TCP `dev_ip:3000`**, sends one framed JSON request, maps the reply into `detectResult`, then closes. Not HTTP `/info`, and not an SSDP wait (detect returns in ~1 s while SSDP NOTIFY may arrive separately via `on_ssdp_msg`).

**Wire — TCP `:3000` frame** (Evidence: pcap `stock_bind_detect_only.pcap` / stock `02.08.01.53` via `plugin_runner --action bind_detect`):

```
A5 A5 | uint16_le total_len | UTF-8 JSON | A7 A7
```

`total_len` is the full frame size including the two magic pairs and the length field.

Request:

```json
{"login":{"command":"detect","sequence_id":"20000"}}
```

Reply:

```json
{"login":{
  "bind":"occupied",
  "command":"detect",
  "connect":"cloud",
  "dev_cap":1,
  "id":"22E8BJ610801473",
  "model":"N7",
  "name":"…",
  "sequence_id":3021,
  "version":"01.02.00.00"
}}
```

Field map into `detectResult`: `command`←`"detect"`, `result_msg`←`"success"`, `dev_id`←`id`, `model_id`←`model`, `dev_name`←`name`, `version`←`version`, `bind_state`←`bind`, `connect_type`←`connect`. `sec_link` is not on this reply (Studio still passes `"secure"` into the ABI).

A printer that refuses to identify itself answers the same session with a `login_report` instead of a `detect` reply — e.g. P1 firmware in LAN-only mode reached from another subnet: `{"login":{"sequence_id":1000,"command":"login_report","status":"FAILURE","reason":"{\"devmsg\":\"LAN-ONLY enabled\",\"err_code\":83902489}"}}` (Evidence: user capture in OrcaSlicer/Studio [OBN #38](https://github.com/ClusterM/open-bamboo-networking/issues/38)).

**Return.** `0` on success. On failure the value must stay inside the compact space the Input IP dialog decodes ([`ReleaseNote.cpp:2044-2057`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/ReleaseNote.cpp#L2044-L2057), Orca [`ReleaseNote.cpp:1949-1963`](https://github.com/SoftFever/OrcaSlicer/blob/v2.4.2/src/slic3r/GUI/ReleaseNote.cpp#L1949-L1963)):

| Return | Studio / Orca reaction |
| --- | --- |
| `-1` | "Failed to connect to printer." + the **Manual Setup** button appears. |
| `-2` | "Failed to publish login request." + the **Manual Setup** button appears. |
| `-3` | Dialog switches straight to the manual name / serial panel (the value Studio hardcodes on macOS instead of calling the plugin). |
| any other negative | Message area is only cleared: no error text, and `update_test_msg` never reveals the **Manual Setup** button, so the manual add flow is unreachable. |

The `-10xx` `BAMBU_NETWORK_ERR_BIND_*` codes belong to `bambu_network_bind`, not here. Stock `02.03.00.62` returns `-2` with `result_msg = "publish login request failed"` even when the TCP connect itself fails, after ~9 s of retries (Evidence: matrix `plugin_runner --action bind_detect --dev-ip 127.0.0.1` with nothing listening on `:3000`).

#### 8.6.3. `bambu_network_bind`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_ip` | `std::string` | Printer LAN IPv4. |
| `dev_id` | `std::string` | Printer serial / device id. |
| `dev_model` | `std::string` | Printer model id (Studio `get_show_printer_type()`). |
| `sec_link` | `std::string` | Bind security link from machine object (`bind_sec_link`). |
| `timezone` | `std::string` | Local UTC offset string (e.g. `UTC+02:00`). |
| `improved` | `bool` | Privacy / improvement opt-in (`e-improved` on wire). |
| `update_fn` | `OnUpdateStatusFn` | Progress; `status` is `BindJobStage` ([§8.6.1](#861-common-contract)). |

**Purpose.** Bind a LAN-visible printer to the logged-in cloud account (account bind from the device card).

**Studio.** [`BindJob.cpp:57-145`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/Jobs/BindJob.cpp#L57-L145): args from the selected `MachineObject` (`dev_ip`, `dev_id`, `dev_model` = `get_show_printer_type()`, `sec_link` = `bind_sec_link`, timezone from local UTC offset, `improved` from notice checkbox / X1 force-false). Callback stages 0…5 map to progress 15/30/45/60/80/100%. `result < 0` → fail UI; `-1040` / `-1080` treat callback `info` as HMS via `stoi`. Success → `update_user_machine_list_info` + `EVT_BIND_MACHINE_SUCCESS`.

**Plugin behaviour.**

1. **LAN ticket mint — TCP `:3000` (same framing as §8.6.2), not MQTT `/request`.** After detect, stock opens a **new** `:3000` session and sends `login.command = "login"` with cloud endpoint hints plus the ABI `timezone` / `improved` flag (Evidence: pcap `stock_account_bind_postreboot.pcap`, stock `02.08.01.53` via `plugin_runner --action account_bind`, printer `bind:free` after reboot):

```json
{"login":{
  "command":"login",
  "sequence_id":"20001",
  "apix":"https://api.bambulab.com/",
  "base_domain":"bambulab.com",
  "iot":"https://api.bambulab.com/v1",
  "emqx":"ssl://us.mqtt.bambulab.com:8883",
  "environment":"",
  "timezone":"UTC+02:00",
  "e-improved":true,
  "tutk":"US",
  "wifi":"US"
}}
```

`timezone` ← ABI `timezone`; `e-improved` ← ABI `improved`. `dev_model` / `sec_link` / `user_id` do **not** appear on this first-bind login body. Region hostnames follow the agent country (`US` → `api.bambulab.com` / `us.mqtt.bambulab.com`).

Printer replies with one or more `login.command = "login_report"` frames on the same TCP session. **Success path** (example ticket `ANXWGM`):

1. `{"login":{"command":"login_report","sequence_id":-1,"status":"wait_auth","ticket":"<T>"}}` — device ticket mint.
2. `{"login":{"command":"login_report","sequence_id":-1,"session_id":0,"status":"SUCCESS"}}` — LAN login accepted (after / interleaved with cloud ticket POST).

Observed failure `login_report` reasons (HMS in `reason.err_code`, also passed to Studio as bind `info` on `-1040`):

| `devmsg` | When |
|----------|------|
| `need logout` | Printer already cloud-bound; stock login body without `user_id` |
| `bind again` | Re-bind to the same account (`status":"SUCCESS"`) when `user_id` is present (manual probe) |
| `tcp binding now` | Printer stuck / busy in an in-progress TCP bind (cleared by printer reboot in one capture) |
| `region or env unmatch` | Login/logout without matching region fields |

2. **Cloud device-ticket validate** (Evidence: MITM `stock_account_bind_postreboot.mitm`, same run as the pcap above): with `T` from `wait_auth`, `GET /v1/user-service/my/ticket/<T>` → `{"source":"device","isValid":true}`, then `POST /v1/user-service/my/ticket/<T>` body `{"ticket":"<T>"}` → `200` empty body. No `POST /v1/iot-service/api/user/bind` in this path.

3. **LAN MQTT after success** (Evidence: earlier `stock_account_bind.log` on `device/<id>/report`): `{"bind":{"bBind":true}}`, then `system.get_access_code`, then `security.app_cert_install` + `printer_cert` ([§10.2](10.02-secrets.md)).

Report progress through `update_fn` using `BindJobStage` values ([§8.6.1](#861-common-contract); observed successful free-printer run: all stages with `code=0`).

**Return.** `0` on success; negative bind error codes on failure.

#### 8.6.6. `bambu_network_request_bind_ticket`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `ticket` | `std::string*` | out: SSO ticket string for WebView. |

**Purpose.** Mint a short ticket for **WebView / MakerWorld SSO** (Print History, MakerLab, external browser). This is not the printer account-bind path in §8.6.3.

**Studio.** Call sites include [`GUI_App`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L7685-L7691) / [L7726-L7732](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L7726-L7732) and [`WebViewDialog`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/WebViewDialog.cpp#L1214-L1225) / [L1304-L1311](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/WebViewDialog.cpp#L1304-L1311) / [L2224-L2234](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/WebViewDialog.cpp#L2224-L2234). On `ret == 0`, Studio opens `{host}api/sign-in/ticket?to=<target>&ticket=<T>` ([GetJumpUrl](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/WebViewDialog.cpp#L1284-L1296)).

**Plugin behaviour.** Two cloud REST calls (Evidence: MITM 2026-07), then write `T` into `*ticket`:

1. `GET /v1/user-service/user/ticket` (Bearer) → `{"ticket":"<T>","pincode":"<T>"}` — mint an unbound web code.
2. `POST /v1/user-service/my/ticket/<T>` with body `{"ticket":"<T>"}` (Bearer) → binds that code to the logged-in session (empty 200 body).

Only after step 2 does MakerWorld `…/api/sign-in/ticket?…&ticket=<T>` set `Set-Cookie: token=<accessToken>` and redirect. If step 2 is skipped, the target still 307s but sets an **empty** `token` cookie; the next navigation 302s to sign-in. Step 1 alone is not enough.

Same `POST …/my/ticket/<T>` path appears in account bind (§8.6.3), but there `T` is a **device** ticket (`GET` first returns `source":"device"`), not the web mint from `GET …/user/ticket`.

**Return.** `0` on success with `*ticket` set; non-zero on failure.

#### 8.6.7. `bambu_network_query_bind_status`

**Plugin behaviour.** Cloud GET (Evidence: MITM `stock_query_bind.mitm`, stock `02.08.01.53` via `plugin_runner --action query_bind`):

- `GET /v1/iot-service/api/user/bind_list?dev_ids=<id>[,<id>…]`
- Bearer + usual `X-BBL-*` / `User-Agent: bambu_network_agent/…`
- On failure stock may retry the same path on the CN failover host (`api.lunkuocorp.com`)
