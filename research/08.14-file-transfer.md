### 8.14. File Transfer ABI (`ft_*`)

Pure-C **tunnel + job** bus exported from the same `libbambu_networking` module as `bambu_network_*`. Studio loads it via `InitFTModule(networking_module)` and resolves bare symbol names with `dlsym` / `GetProcAddress` ([FileTransferUtils.cpp:11-37](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/FileTransferUtils.cpp#L11-L37)). Typedefs and wrappers: [FileTransferUtils.hpp:27-95](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/FileTransferUtils.hpp#L27-L95). Calling convention: `__cdecl` on Windows (`FT_CALL`).

LAN jobs ride TLS **`:6000`** (framing, handshake, `cmdtype` 4/5/7 flows — [§6.4](06.04-port-6000.md)). Remote tunnels reuse `bambu:///tutk?…` URLs minted by [§8.11](08.11-camera.md). Device → Files browsing uses the same wire through `libBambuSource` ([§9](09-abi-bambusource.md)), **not** these symbols.

Neighbors: `:6000` protocol ([§6.4](06.04-port-6000.md)); print start / `brtc://` ([§8.8](08.08-print-abi.md)); FTPS probe / fallback `start_send_gcode_to_sdcard` ([§8.8.6](08.08-print-abi.md#886-bambu_network_start_send_gcode_to_sdcard)); camera URL mint ([§8.11](08.11-camera.md)); BambuSource CTRL ([§9](09-abi-bambusource.md)).

The `ft_job_result` layout below is independently confirmed in [issue #49](https://github.com/ClusterM/open-bambu-networking/issues/49) (disassembly of `ft_job_result_destroy`).

#### 8.14.1. Common contract

**Types** ([FileTransferUtils.hpp:27-45](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/FileTransferUtils.hpp#L27-L45)):

```cpp
typedef enum {
    FT_OK = 0, FT_EINVAL = -1, FT_ESTATE = -2, FT_EIO = -3,
    FT_ETIMEOUT = -4, FT_ECANCELLED = -5, FT_EXCEPTION = -6,
    FT_EUNKNOWN = -128
} ft_err;

struct ft_job_result { int ec; int resp_ec; const char *json; const void *bin; uint32_t bin_size; };
struct ft_job_msg    { int kind; const char *json; };
```

| Struct | Field | Meaning |
| --- | --- | --- |
| `ft_job_result` | `ec` | Job-level error (`0` = success). Studio SendToPrinter treats `ec == 0` as success for ability/upload. |
| `ft_job_result` | `resp_ec` | Printer / protocol response code when distinct from `ec` (wire `result` / firmware code). Shown in Studio error strings via `ParseErrorCode(resp_ec)` on ability failure. |
| `ft_job_result` | `json` | Optional UTF-8 JSON (ability label array; download final `reply`; error object). Plugin-owned until destroy. |
| `ft_job_result` | `bin` / `bin_size` | Optional binary payload (mem-download JPEG). Plugin-owned until destroy. |
| `ft_job_msg` | `kind` | Message class. Observed: `0` = progress (`{"progress":N}`). |
| `ft_job_msg` | `json` | Message body string. Plugin-owned until destroy. |

Studio copies `json` / `bin` out of callbacks, then calls `ft_job_result_destroy` / `ft_job_msg_destroy` (falling back to `ft_free` on the pointers if destroy is missing).

**ABI version.** `InitFTModule` defaults `abi_required = 1`; Studio expects `ft_abi_version() == 1`.

**Lifecycle.**

```text
ft_tunnel_create(url) → set_status_cb → start_connect | sync_connect
ft_job_create(params_json) → set_result_cb → [set_msg_cb] → ft_tunnel_start_job
  … msg_cb(progress) …
  result_cb(ft_job_result) → ft_job_result_destroy
ft_job_release / ft_tunnel_shutdown / ft_tunnel_release
```

Typical Studio wrappers: `FileTransferTunnel` / `FileTransferJob` in `FileTransferUtils.cpp`; Send-to-Printer in [`SendToPrinter.cpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/SendToPrinter.cpp); mem preview in [`FileTransferObject.cpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/FileTransferObject.cpp).

**Tunnel URL.** Studio builds LAN URLs itself:

```text
bambu:///local/<ip>?port=6000&user=bblp&passwd=<access_code>
```

(sometimes `<ip>.` with a trailing dot — see SendToPrinter / MediaPlayCtrl). Remote: `bambu:///tutk?uid=…` after [§8.11](08.11-camera.md) `get_camera_url`. Plugin opens TLS `:6000` or the TUTK relay and runs the [§6.4](06.04-port-6000.md) handshake.

**Job JSON** (`params_json` for `ft_job_create`) — ABI layer; wire shapes differ ([§6.4](06.04-port-6000.md)):

| `cmd_type` | Studio caller | `params_json` keys | Result |
| ---: | --- | --- | --- |
| `7` | `CreateMediaAbilityJob` | `{"cmd_type":7}` | `json` = storage label array, e.g. `["emmc","udisk"]` |
| `5` | `CreateUploadFileJob` | `cmd_type`, `dest_storage`, `dest_name`, `file_path` | `ec`/`resp_ec` success; progress via `msg_cb` |
| `4` | `DownloadMemFile` | `cmd_type`, `path`, `is_mem_file`, `target_path` | `bin` = JPEG; wire omits `is_mem_file` |

**ABI → wire mapping** (detail in [§6.4](06.04-port-6000.md)):

| `ft_job` `cmd_type` | Wire `cmdtype` | Notes |
| ---: | ---: | --- |
| `7` | `0x0007` | `REQUEST_MEDIA_ABILITY` |
| `5` | `0x0005` | Chunked `FILE_UPLOAD` (`dest_storage` → wire `storage`, `dest_name` → `path`) |
| `4` | `0x0004` | `FILE_DOWNLOAD` — wire `{path, offset}` only |

**Progress messages.** Upload jobs: `msg_cb` with `kind == 0` and JSON `{"progress":N}` (0–100). Stock derives `N` from bytes written during the pipelined send, not from per-chunk wire ACKs ([§6.4](06.04-port-6000.md)).

**Not this ABI.** Bulk Send-to-Printer on brtc printers is `ft_*` / `:6000`. FTPS `:990` write probe / rare non-brtc fallback is `bambu_network_start_send_gcode_to_sdcard` ([§8.8.6](08.08-print-abi.md#886-bambu_network_start_send_gcode_to_sdcard)).

**TODO**: need confirmation of `cmd_type` values beyond 4/5/7; numeric meanings of tunnel status / conn-callback `err` codes; `msg.kind` values other than `0`; full remote/TUTK upload path vs LAN.
