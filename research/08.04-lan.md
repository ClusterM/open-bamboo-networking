### 8.4. Local printer connection (LAN)

LAN discovery (SSDP) and the direct printer MQTT session live next to the cloud path ([§8.3](08.03-cloud-mqtt.md)). Typedefs for these entry points are in [`NetworkAgent.hpp`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/NetworkAgent.hpp#L40-L45); Studio resolves them via `dlsym` / `GetProcAddress` ([NetworkAgent.cpp:315-320](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/Utils/NetworkAgent.cpp#L315-L320)). Inbound events (`on_ssdp_msg`, `on_local_connect`, `on_local_message`, `on_printer_connected`) are registered separately ([§8.2](08.02-callbacks.md)).

Wire: SSDP ([§6.1](06.01-ssdp.md)), LAN MQTT URL/auth/topics and dual-session policy ([§6.2](06.02-mqtt.md)), TLS leaf / access-code security ([§10.6](10.06-lan-tls-and-access-codes.md)), app-cert provisioning ambiguity ([§10.2](10.02-secrets.md)), JSON catalogues ([§12](12-mqtt.md)).


| Symbol                                   | Signature                                                                                         | Notes                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| `bambu_network_start_discovery`          | `bool(void* agent, bool start, bool sending)`                                                     | SSDP listen                                                           |
| `bambu_network_connect_printer`          | `int(void*, std::string dev_id, std::string dev_ip, std::string username, std::string password, bool use_ssl)` | LAN MQTT open                                                         |
| `bambu_network_disconnect_printer`       | `int(void* agent)`                                                                                | Tear LAN MQTT                                                         |
| `bambu_network_send_message_to_printer`  | `int(void*, std::string dev_id, std::string json_str, int qos, int flag)`                         | LAN twin of `send_message`                                            |
| `bambu_network_update_cert`              | `int(void* agent)`                                                                                | Studio method `check_cert` / `func_check_cert` — **not** `bambu_network_check_cert` |
| `bambu_network_install_device_cert`      | `void(void* agent, std::string dev_id, bool lan_only)`                                            | Device trust provision                                                |


#### 8.4.1. Common contract / sequence

**Return convention.** Most entry points return `int`: `0` on success, or a `BAMBU_NETWORK_ERR_*` code ([§8.16](08.16-errors.md)) — e.g. `CONNECT_FAILED` (−2), `DISCONNECT_FAILED` (−3), `SEND_MSG_FAILED` (−4), `CONNECTION_TO_PRINTER_FAILED` (−6010). `start_discovery` returns `bool`. `install_device_cert` returns `void`. Studio **ignores** most `int`/`bool` returns on this surface; the value that matters in practice is the `int` from `send_message_to_printer` (propagated through `publish_json`). Connect success/failure UX is async via [`on_local_connect`](08.02-callbacks.md) / [`on_printer_connected`](08.02-callbacks.md) ([§8.2.12](08.02-callbacks.md)–[§8.2.13](08.02-callbacks.md)), not the connect `int`.

**Lifecycle.**

1. After init, Studio installs SSDP / HTTP-error callbacks then `start_discovery(true, false)` ([§8.1.1](08.01-initialization.md), [§8.2.3](08.02-callbacks.md)).
2. SSDP fills LAN IP for known `dev_id`s ([§6.1](06.01-ssdp.md)).
3. **LAN-mode** selection (`connection_type == "lan"`) → `MachineObject::connect` → `connect_printer`. Cloud-mode selection uses `set_user_selected_machine` ([§8.7](08.07-printer-selection.md)), **not** `connect_printer`.
4. Plugin fires `on_local_connect` / `on_printer_connected` → Studio may `install_device_cert`, request push_all / version / access code.
5. Commands on a LAN-mode printer go through `publish_json` → `send_message_to_printer`.
6. Leaving or re-selecting a LAN machine → `disconnect_printer` (then reconnect if same id).
7. `update_cert` once from `post_init` via `GUI_App::check_cert`. Refresher (~1 s) re-calls `install_device_cert` for the selected machine.
8. Windows shutdown: `start_discovery(false, false)` before `destroy_agent`.

**Where LAN credentials come from.** A LAN MQTT session needs **IP** + **access code**:

| Half | LAN-Only / Developer Mode | Cloud-paired |
|------|---------------------------|--------------|
| IP | UI / SSDP | SSDP `NOTIFY` (`dev_id` + LAN IP) via `start_discovery` |
| Access code | Printer screen / UI | Cloud REST `dev_access_code` from `get_user_print_info` / bind ([§8.10](08.10-http.md)); also cached in app config |

Username is typically `"bblp"`. `use_ssl` comes from `MachineObject::local_use_ssl_for_mqtt` (default `true` in release builds).

**Cloud dual-session (fact).** Open Studio call sites invoke `connect_printer` only for **LAN-mode** selection. Opening a LAN MQTT session for a **cloud-paired** printer (LAN-priority reports in [§6.2](06.02-mqtt.md)) is **stock plugin** behaviour when IP + access code are known — not a second Studio call of `connect_printer` for `connection_type == "cloud"`. A compatible plugin must still accept those credentials when `connect_printer` is invoked (Studio LAN-mode path, or the plugin’s own dual-session path).

#### 8.4.2. `bambu_network_start_discovery`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `start` | `bool` | `true` = start SSDP listener; `false` = stop. |
| `sending` | `bool` | `true` = also send M-SEARCH; Studio cold-boot uses `false`. |

**Purpose.** Start or stop the SSDP / LAN discovery listener.

**Studio.** [`post_init`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1362-L1378) and [`restart_networking`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1943-L1960) call `(true, false)` after (re)installing `set_on_ssdp_msg_fn`. On Windows shutdown ([GUI_App.cpp:2854-2858](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2854-L2858)): `(false, false)` before `delete m_agent`. Return ignored. `sending` is always `false` in observed Studio calls.

**Plugin behaviour.** When `start` is true, listen for printer UDP NOTIFY on `:2021` and deliver JSON via `on_ssdp_msg` ([§8.2.3](08.02-callbacks.md), wire [§6.1](06.01-ssdp.md)). When false, stop the listener. `sending` may be ignored if unused.

**Return.** `bool` — Studio ignores it (wrapper default `false` if symbol missing).

#### 8.4.3. `bambu_network_connect_printer`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_id` | `std::string` | Printer serial / device id. |
| `dev_ip` | `std::string` | Printer LAN IPv4. |
| `username` | `std::string` | LAN MQTT username (Studio uses `bblp`). |
| `password` | `std::string` | LAN access code. |
| `use_ssl` | `bool` | LAN MQTT over TLS (`true` for secure printers). |

**Purpose.** Open a LAN MQTT session to a printer.

**Studio.** Only from LAN-mode [`DeviceManager::set_selected_machine`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L573-L611) → [`MachineObject::connect`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.cpp#L2330-L2343): `(dev_id, dev_ip, "bblp", get_access_code(), use_ssl)`. Empty IP returns `-1` without calling the ABI. Studio’s `int` return is **ignored**; UX uses [`on_local_connect`](08.02-callbacks.md) / [`on_printer_connected`](08.02-callbacks.md). Cloud-mode selection uses `set_user_selected_machine` instead ([L597-601](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L597-L601)).

**Plugin behaviour.** Connect to `mqtts://<dev_ip>:8883` when `use_ssl` (plaintext `:1883` only if explicitly requested — stock Studio uses TLS). Authenticate with `username`/`password` (typically `bblp` + 8-char access code). Fire local-connect / printer-connected callbacks. Wire details: [§6.2](06.02-mqtt.md), [§10.6](10.06-lan-tls-and-access-codes.md).

**Return.** `0` on success; non-zero on failure (Studio ignores on the selection path).

#### 8.4.4. `bambu_network_disconnect_printer`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |

**Purpose.** Tear down the current LAN MQTT printer session.

**Studio.** When leaving a LAN-mode selection for another machine ([DevManager.cpp:541-548](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L541-L548)), and before same-LAN reconnect ([L580-582](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L580-L582)). Leaving a cloud selection uses `set_user_selected_machine("")`, not this call. Return ignored. `MachineObject::disconnect` wraps the ABI but has no other live callers on this pin.

**Plugin behaviour.** Close the LAN MQTT session and stop delivering `on_local_message` for that link. Idempotent if already disconnected.

**Return.** `0` on success; non-zero on failure (Studio ignores).

#### 8.4.5. `bambu_network_send_message_to_printer`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_id` | `std::string` | Printer serial / device id. |
| `json_str` | `std::string` | MQTT JSON payload to publish. |
| `qos` | `int` | MQTT QoS (0/1/2). |
| `flag` | `int` | `MessageFlag` bits ([§8.3.1](08.03-cloud-mqtt.md#831-common-contract-sequence)); Studio default `0`. |

**Purpose.** Publish an opaque JSON command envelope on the **LAN** MQTT channel.

**Studio.** [`MachineObject::local_publish_json`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.cpp#L2455-L2461) → `send_message_to_printer(get_dev_id(), json_str, qos, flag)`. Router [`publish_json`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceManager.cpp#L2428-L2443) uses this when `is_lan_mode_printer()`; otherwise cloud [`send_message`](08.03-cloud-mqtt.md) ([§8.3.10](08.03-cloud-mqtt.md)). Defaults `qos=0`, `flag=0`; many commands pass `qos=1`. Return **propagated** to command callers. Payload shapes: [§12](12-mqtt.md).

**Plugin behaviour.** Publish `json_str` on the LAN request topic for `dev_id` ([§6.2](06.02-mqtt.md)). Honour `qos` / `flag` as for the cloud twin. Return a real error code on failure.

**Return.** `0` on success; non-zero `BAMBU_NETWORK_ERR_*` (e.g. `SEND_MSG_FAILED`) on failure.

#### 8.4.6. `bambu_network_update_cert`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |

**Purpose.** Fetch / refresh the shared Studio **app** cert + CRL (+ encrypted private-key blob) from the cloud (Studio method name: `check_cert`).

**Studio.** [`GUI_App::check_cert`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5683-L5690) runs `m_agent->check_cert()` on a background thread; invoked from `post_init` ([GUI_App.cpp:1358](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L1358)). Return ignored. Export symbol is **`bambu_network_update_cert`**, not `bambu_network_check_cert`. In a cold Studio start this is typically the **first** `bambu_network_agent/…` HTTPS call.

**Plugin behaviour.** Perform the shared app-cert cloud fetch documented in [§10.2](10.02-secrets.md):

```
GET /v1/iot-service/api/user/applications/{enc_secret}/cert?aes256={wrapped_session_key}&ver=1
```

Evidence: `plugin_runner --action update_cert` against stock `02.08.01.53` under mitmproxy — the sole HTTPS request was that GET; HTTP 200 with `cert` / `crl` / `key`; **no** `Authorization` when not logged in. When a session is present (Studio cold start with persisted login), stock still attaches `Authorization: Bearer …` (optional for the server). Must be safe to call off the GUI thread. Stock may also re-hit this endpoint later when other cloud paths need fresh app credentials (observed interleaved with `http_probe` / `mw_probe` traffic).

**Return.** `0` on success; non-zero on failure (Studio ignores).

#### 8.4.7. `bambu_network_install_device_cert`

**Parameters.**

| Name | Type | Meaning |
| --- | --- | --- |
| `agent` | `void*` | Opaque agent from `create_agent`. |
| `dev_id` | `std::string` | Printer serial / device id. |
| `lan_only` | `bool` | Studio `is_lan_mode_printer()`; LAN vs cloud-paired device. |

**Purpose.** Ask the plugin to provision / install device trust material for a printer.

**Studio.** Always `(obj->get_dev_id(), obj->is_lan_mode_printer())` — `lan_only` is true iff `connection_type == "lan"`:

- After [`on_printer_connected`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L2131-L2155) (with push_all / get_version / access-code refresh).
- [`DeviceManagerRefresher::on_timer`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/DeviceCore/DevManager.cpp#L1008-L1009) (~1 s while a machine is selected).
- Plugin message `"wait_info"` via [`process_network_msg`](https://github.com/bambulab/BambuStudio/blob/12f17b06f4f537f9c03162d08bb70cf733c42839/src/slic3r/GUI/GUI_App.cpp#L5696-L5704).

Related inbound msgs `"device_cert_installed"` / `"device_cert_uninstalled"` update Studio UI state — not separate ABI exports.

**Plugin behaviour.** Install or refresh device-side trust for `dev_id` by publishing MQTT `security.app_cert_install` ([§10.2](10.02-secrets.md)), then notify Studio with the string message `"device_cert_installed"` (via the message callback / `process_network_msg`). `lan_only` distinguishes LAN-mode printers from cloud-paired ones.

Evidence (LAN path, stock Studio / agent on `22E8…`, mqtt_logger on `device/<id>/request|report`, 2026-07-27):

**Request** `device/<dev_id>/request` (qos 0):

```json
{
  "security": {
    "command": "app_cert_install",
    "sequence_id": "<str>",
    "app_cert": "<PEM: app leaf + app intermediate + application_root>",
    "crl": "<PEM: X509 CRL>"
  }
}
```

Observed: 3 PEMs in `app_cert`, 1 CRL in `crl`.

**Report** `device/<dev_id>/report` (same `sequence_id`):

```json
{
  "security": {
    "command": "app_cert_install",
    "printer_cert": "<PEM: device leaf + Device CA>",
    "result": "SUCCESS",
    "sequence_id": "<str>"
  }
}
```

ABI side: `plugin_runner --action cert_probe` with `lan_only=true` also fired `on_message(dev_id, "device_cert_installed")` within ~150 ms of the call. A second call with `lan_only=false` on the same already-provisioned LAN session produced no extra MQTT traffic (idempotent skip / needs a cloud-selected machine — not fully mapped).

**Return.** `void`.

Hub: [§8](08-abi-main.md).
