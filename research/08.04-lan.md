### 8.4. Local printer connection (LAN)

| Symbol | Signature |
|--------|-----------|
| `bambu_network_connect_printer` | `int(void*, std::string dev_id, std::string dev_ip, std::string username, std::string password, bool use_ssl)` |
| `bambu_network_disconnect_printer` | `int(void*)` |
| `bambu_network_send_message_to_printer` | `int(void*, std::string dev_id, std::string json_str, int qos, int flag)` |
| `bambu_network_update_cert` | `int(void* agent)` — `func_check_cert`; refreshes certificates at runtime |
| `bambu_network_install_device_cert` | `void(void*, std::string dev_id, bool lan_only)` |
| `bambu_network_start_discovery` | `bool(void*, bool start, bool sending)` — SSDP |

`connect_printer` opens LAN MQTT (`mqtts://<ip>:8883` when `use_ssl`, user typically `bblp`, password = 8-character access code). `send_message_to_printer` publishes opaque JSON on that session. `start_discovery` runs the SSDP listener on UDP `:2021`.

#### 8.4.1. Where the LAN credentials come from (incl. cloud-paired printers)

A LAN session needs **IP** + **access code**. In LAN-Only / Developer Mode both come from the UI (code on the printer screen). For a **cloud-paired** printer:

- **IP** ← SSDP `NOTIFY` (`dev_id` + LAN IP) via `start_discovery`
- **Access code** ← cloud REST `dev_access_code` (plaintext) from `get_user_print_info` / bind ([§8.10](08.10-http.md))

With both halves, `connect_printer(…, "bblp", <code>, true)` works even though the device is cloud-paired — which Studio’s LAN-priority report subscription relies on ([§6.2](06.02-mqtt.md)).

Security details (plaintext access codes, LAN TLS leaf `CN=<serial>`, `printer.cer` gaps): [§10.6](10.06-lan-tls-and-access-codes.md).
